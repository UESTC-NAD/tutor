第五到第九章，只留脉络

这一页不装细节。每章只有三样：这一章在解决什么问题、逼出后面所有内容的那条因果链、你必须知道「存在」的那几个名词——名词只给一句「它是干什么的」，不给字段、不给数字、不给流程。

看完你应该能做到：听见任何一个术语，能立刻说出它属于哪一章、是用来补哪个洞的。剩下的考场上现查。

先把五章挂到协议栈上

这五章不是并列的五个话题，是从下往上走了一遍协议栈。知道每章站在哪一层，比记住章名有用得多。

🔑 挂上去之后，最该记住的一句话 每一层都各自重新发明了一次「认证 + 完整性 + 加密」。
因为下层保不了上层：链路层加密只保一段链路，出了这个局域网就没了；IP 层保的是两个 IP 之间的管子，管不了「哪个用户在用」；传输层的 SSL 只保护调用了它的那个应用；到了应用层，管子再安全，管子那头的程序照样会把用户输入当命令执行。
所以 WEP/WPA、IPSec、SSL/TLS、DNSSEC、HTTPS 这五套东西，做的是同一件事的五个副本——这就是为什么它们长得那么像。

再看一遍：五章其实是同一个故事

每一章的病根都能压成同一句话：某个协议在设计时假定「对面是好人」，于是把「你是谁」交给一个不需要密钥就能造出来的凭据去担保。

章出问题的协议它拿什么当「真实性凭据」为什么靠不住补丁

6IPv4首部里的源地址发送方自己填的，没人查；检验和也明文可重算IPSec
7TCP序列号明文可见 → 抄；有规律 → 猜SSL / TLS

CH 5

无线网络安全

WEP → WPA → WPA2 → WPA3　+　移动通信 2G → 5G
病根

有线网络里，偷听要先物理接触那根线——门槛不高，但真实存在。无线把这道门槛整个拆了：频段公开、信号穿墙、被动收听不留痕迹。既然物理隔离没有了，就只能用密码学补回来——补三样：认证、完整性、加密。后面四个协议做的全是这一件事。

因果链每个协议都在补上一个的漏

WEP→ 三个漏：密钥太短会用完、校验值不要密钥、认证是单向的→ WPA 换密钥、换校验值→ 但为了能用旧硬件，加密算法没换→ WPA2 换成 AES→ 加密解决了，那密钥是怎么协商出来的？→ 四次握手（顺便补上双向认证）→ 握手可以被逼着重来一遍，同一段密钥流就用了两次→ KRACK→ WPA3
🔑 一句话 这一章从头到尾只在讲：流密码的密钥流绝对不能重用。WEP 是因为密钥太短用完了，KRACK 是因为计数器被重置了——相隔十几年、两个不同的协议，栽在同一个坑里。

名词必须知道存在的东西

WEP / WPA / WPA2 / WPA3
四代无线加密协议，一代补一代的漏
TKIP / CCMP
WPA 和 WPA2 各自的加密协议（CCMP 是基于 AES 的那个）
ICV / MIC
WEP 和 WPA 各自的完整性校验值——区别只在要不要密钥
四次握手
连上 Wi-Fi 时协商会话密钥的过程，顺带互相认证
KRACK
逼客户端重装密钥的攻击。注意：它破坏机密性，但破解不了你的 Wi-Fi 密码
802.1x / WPA-PSK
企业模式 / 个人模式。区别只在主密钥从哪来，之后完全一样
AKA
移动网络（3G 起）的双向认证机制。2G 只有单向 → 所以有伪基站
CH 6

数据链路层和网络层安全

链路层风险 → 网络层风险 → IPSec（全章重心）→ 路由安全
病根

IPv4 首部里那个「源地址」，是发送方自己填进去的一串数字，没有任何东西证明它是真的——信封上写谁的地址都行，邮局不查。而「首部检验和」是明文可重算的，它防的是线路噪声，不是防人。这一章就是给一个从设计上就不设防的协议，补上认证、加密和密钥管理。

因果链责任一层层往上推，推到 IPSec 才收口

链路层：谁都能看见谁（混杂模式是硬件的默认能力，不是漏洞）→ 补丁：MAC 白名单、CHAP→ 补不住，而且只保一段链路→ 推给网络层→ 网络层自己也不设防（路由表能被毒、地址能冒充）→ 工程手段：NAT、过滤、私网地址——都是「让攻击者够不着」，不是密码学→ 只能上密码学：IPSec→ 但 IPSec 只保护「包」，保护不了「路怎么走」→ 路由协议安全（RIP / OSPF / BGP）
🔑 一句话 IPSec 为什么做在 IP 层？因为下面的链路层只能保一段，上面的应用层要一个个改。做在 IP 层对上层协议和用户完全透明——不用改一行应用代码。这是它全部优点的来源。

名词必须知道存在的东西

AH / ESP
IPSec 的两个协议：AH 只认证，ESP 还能加密
传输模式 / 隧道模式
保护载荷 / 把整个原包包起来再套个新头。一方是路由器或网关就必须用隧道
SA / SPD
SA =「这条连接用哪把密钥、哪个算法」；SPD =「哪些流量需要保护」
IKE
密钥是怎么协商出来的。它补的是 Diffie-Hellman 的两个毛病：不认身份、算得太慢
NAT
地址转换，顺带有防火墙效果。它和 AH 天生冲突（AH 认证了 IP 地址，NAT 恰恰改它）
ARP 投毒
局域网里改别人的地址对照表 → 做 DoS 或中间人
BGP 路由劫持
路由协议无条件相信邻居的通告 → 把流量整片引走
CH 7

传输层安全

上半章：裸 TCP 为什么必然被打　下半章：SSL / TLS 怎么逐个堵死
病根

TCP 把「谁在说话」这件事，交给了一个明文的序列号来担保。于是：看得见的人能改、猜得中的人能冒充、发得快的人能拖垮它。改端口、装防火墙、上 IDS 全是外围补丁，根子一个没解决——TCP 报文本身既不加密也不认证。既然改不动 TCP，就在它上面加一层。

因果链四个子协议不是并列的，是被逼出来的

要机密性 + 完整性 + 认证→ 就要密钥→ 密钥要协商 ⇒ 握手协议→ 协商出来要派生 ⇒ 密钥生成→ 派生出来要用 ⇒ 记录协议→ 新旧密钥切换要同步 ⇒ 变更规格协议→ 出错和关闭要可认证 ⇒ 告警协议
🔑 两句话 ① 为什么加在传输层？网络层太低（点对点，管不到「哪个用户」），应用层太散（每个应用都要重写一遍），传输层刚好。
② 记这个顺序就够了：协商（握手）→ 派生（密钥生成）→ 使用（记录）→ 切换（变更规格）→ 收场（告警）。

名词必须知道存在的东西

握手 / 记录 / 变更规格 / 告警
SSL 的四个子协议。握手只产出参数，记录协议才真的加密
连接 vs 会话
会话存参数，连接干活。一次握手的成果可以被多条连接共用
SYN Flood
把半开的连接队列塞满。SSL 挡不住它——可用性不在 SSL 的服务范围内
会话拦截（全会话 / 盲）
看得见序列号的抢答，看不见的猜号
IDS / IPS
分界就在七个字：部署在数据转发路径上。IDS 只告警，IPS 能拦
TLS
SSL 的标准化版本。PPT 没讲但课本习题考，主要改的是把自创的构造换成有安全性证明的标准构造
SSL VPN
SSL 只护「调用了它的那个应用」，VPN 让它能护任意应用
CH 8

DNS 安全

上半章：DNS 为什么必然被骗　下半章：DNSSEC 怎么让骗被当场识破
病根

DNS 诞生在一个「上网的人彼此都认识」的年代，设计基础是互相信任。协议里根本没有「验明正身」这一步——谁先把一个长得像回答的包送到你面前，你就信谁。后面所有攻击都是这同一句话的不同玩法。

因果链从「互相信任」到「自带签名」

层次 + 分布式解决了规模，但没解决真假→ 只好用一个短短的事务 ID 当凭据→ 能监听就抄，抄不到就猜；谁抢先送到谁赢→ 而 DNS 会缓存，缓存多久由攻击者在假回答里自己填→ 骗一次 → 骗很久，还传染给所有人（缓存投毒）→ 补丁只是「让猜变难」，而路径上的人根本不用猜→ 唯一出路：让数据自带证据 = DNSSEC→ 那公钥本身谁来证明？交给父区签名 → 信任链→ 还剩一件事没解决：不加密 → DoH / DoT
🔑 一句话 DNS 的所有安全问题，都源自「它没办法证明一个回答是谁说的」；DNSSEC 的所有设计，都是在补这一件事——而它补完之后，「谁看见了你在问什么」这个问题还原封不动地留在那里。

名词必须知道存在的东西

递归 / 迭代查询
「你帮我查到底」/「我不知道但我知道该问谁」。一次查询里两者同时存在
缓存投毒
骗的不是一个人一次，是一台解析器的持久记忆——种下之后攻击者可以下线
DNSSEC
给 DNS 记录加数字签名。三项功能：来源验证、完整性验证、否定存在验证
DNSKEY / RRSIG / NSEC / DS
公钥 / 签名 / 证明「不存在」 / 把子区公钥的散列交给父区保管
信任链 / 信任锚
一层层往上验到根。停在根不是因为验过了，是因为根的公钥被预装在你机器里
ZSK / KSK
两对密钥：一把常换（不惊动父区），一把长期用（换它要通知父区）
DoH / DoT
补 DNSSEC 剩下的那件事：隐私。签名不等于加密
⚠ 最反直觉的一条 部署了 DNSSEC，反射式 DDoS 不但没变好，反而更糟——它验的是「回答」不是「提问」，而签名让报文更大，放大倍数更高。
CH 9

Web 应用安全

体系结构脆弱性 → 七种攻击（全章重头）→ HTTPS → QUIC → WAF
病根

前面四章的防护都在保护「传输」。但 SQL 注入的那条请求既没被偷看也没被篡改——它就是用户自己敲进去的，规规矩矩从 443 端口加密传到服务器，然后服务器自己把它拼进了一条 SQL 语句。
Web 应用会把外部输入拼进某种「解释器」能读懂的语句里，而拼接时分不清哪段是代码、哪段是数据。换一个解释器，就换一个漏洞名字。

因果链一个病根，十种病灶

HTTP 无状态→ 用 Cookie 补→ Cookie 在用户手里，能改也能被听走· 另一条线：输入被拼进解释器→ 拼进 SQL、HTML、Shell、文件路径、响应头 = 五种注入→ 共同解法：让解释器自己区分代码与数据→ 但如果请求字字合法，只是不是用户本意呢 ⇒ CSRF→ 应用补完了，链路还是明文 ⇒ HTTPS→ 80 端口还开着 ⇒ SSL 剥离 ⇒ HSTS→ 握手太慢、还有队头阻塞 ⇒ QUIC / HTTP3→ 代码改不完、0day 补不上 ⇒ WAF
🧭 一句话记住整章 前半章是「服务器分不清代码和数据」，后半章是「浏览器分不清对面是谁」。
七种攻击属前者；HTTPS / HSTS 属后者；QUIC 是后者的效率改良（不是更安全）；WAF 是给前者打的补丁（不修漏洞，只买时间）。

名词必须知道存在的东西

SQL 注入
拼进数据库 → 拖走网站的数据。根治：参数化查询
XSS
拼进 HTML → 打的是其他用户。根治：输出时做实体编码
OS 命令注入 / 目录遍历 / 头注入
分别拼进 Shell、文件路径、HTTP 响应头——同一个病根的另外三个名字
CSRF
请求合法、Cookie 也是真的，只是不是用户本意。所以输入校验一个字都挑不出毛病
Cookie 欺骗 / 会话劫持
编一个 vs 偷一个
HTTPS / HSTS / SSL 剥离
加密链路 / 强制走加密 / 把用户悄悄退回明文的攻击
QUIC / HTTP3
把加密内建进传输协议。价值在效率，不在「更安全」
WAF
看得懂 HTTP 内容的墙。网络防火墙管「谁能进门」，WAF 管「进门的人手里拿的是什么」

跨章主线：五个「其实是同一道题」

这一节是框架里最值钱的部分。简答题最爱问「比较 / 分析 / 为什么」，而下面每一条都横跨好几章——记住一条，等于同时准备了三四道题；更重要的是，它能让你在考场上认出一道没见过的题属于哪一类。

01单向认证 → 必然出现「假冒服务方」

WEP 只有 AP 验设备　→　假冒 AP　5
2G 只有网络认证用户　→　伪基站　5
DNS 客户端无法认证应答方　→　假应答 / 缓存投毒　8
HTTP 浏览器无法认证服务器　→　中间人 / SSL 剥离　9
补法也永远一样：做成双向——WPA 的四次握手、3G 的 AKA、DNSSEC 的签名、HTTPS 的证书。

02没有密钥的校验值，只防噪声不防人

WEP 的 CRC-32：不要密钥 → 改内容顺手改校验值　5
IP 首部检验和：明文可重算 → 同上　6
换成带密钥的 MAC / 签名就解决了：WPA 的 MIC、IPSec 的 ICV、SSL 记录协议的 HMAC、DNSSEC 的签名。这四个东西是同一个思路的四个名字。

03「谁先送到我就信谁」

TCP 认序列号对得上的那个包　7　｜　DNS 认第一个到达的应答、扔掉后面的　8
所以两边的攻击套路完全一样：先把真的那一方 DoS 掉，把「比谁快」的赌局变成「对手跑不动」的稳赢局。看到题目里出现「先对某某发起拒绝服务」，多半就是这一类。

04加密解决不了「资源被耗尽」

SSL 挡不住 SYN Flood——可用性根本不在 SSL 的服务范围内　7
DNSSEC 挡不住反射放大，反而更糟　8
HTTPS 挡不住应用层的洞——注入请求本来就是加密送达的　9
凡是问「加了 X 之后还能防住 Y 吗」，先分清 Y 打的是「真实性 / 机密性」还是「可用性」——是后者，答案基本都是「不能」。

05把「数据」当成「指令」执行

路由协议无条件相信邻居的通告 → 路由劫持　6
解析器无条件相信收到的应答 → 缓存投毒　8
应用把外部输入拼进解释器 → 五种注入　9
越往上层，「数据」被当成「指令」执行的后果越直接。
