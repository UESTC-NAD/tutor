Chapter 6 · Data-Link & Network Layer Security

数据链路层和网络层安全

TCP/IP 这套协议诞生在一个「网上都是熟人」的年代。IP 首部里没有一个字段是用来证明「我是谁」的——源地址是发送方自己填的，谁都能改；内容没有任何校验能挡住蓄意篡改；数据全程明文。这一章讲的就是：在一个从设计上就不设防的协议栈里，怎么把安全补回去。

本页按老师 PPT 的顺序和详略组织。PPT 共 145 页，其中 IPSec 占了 78 页（54%）——这是本章唯一的重心。每一节先给 PPT 抛出的真实问题，再讲机制，最后说明它留下了什么新问题。链路层 → 网络层 → IPSec 是一条完整的因果链：每一层都在补下一层堵不住的洞。

PPT 第 34 页 · 全章的出发点

IPv4 协议本身，到底缺了什么？

PPT 原文只列了三条，一条比一条要命：

PPT p.34「IPv4 安全性分析」原文
  • IPv4 协议没有认证机制 —— 没有消息源认证（源地址假冒）、没有完整性认证（篡改）
  • IPv4 没有加密机制 —— 无机密性（监听应用数据）、泄露拓扑等信息（网络侦察）
  • 无带宽控制 —— DDoS 攻击

把它翻译成人话。IP 首部里有个「源地址」字段，那是发送方自己填进去的一串数字，没有任何东西证明它是真的。你在信封上写谁的地址都行，邮局不查。

而首部里那个「首部检验和」呢？它是明文可重算的——攻击者改完内容，顺手把检验和也重算一遍，接收方一点都察觉不到。检验和防的是线路噪声，不是防人。

于是这一章的任务就定死了：给一个从设计上就不设防的协议，补上「认证 + 加密 + 密钥管理」。课本 p.161 一句话点题：「为了解决 IPv4 存在的安全问题，IETF 设计了一套端到端的确保 IP 通信安全的机制，称为 IPsec。IPsec 提供三种功能：认证、加密和密钥管理。」课本 p.161

★ 这三条本身就是一道简答题

课本习题简答第 1 题「分析攻击者可以利用 IPv4 协议的哪些特性进行网络攻击」，标准答案就是这三条的合并：「IPv4 协议的无连接、无认证、无加密、无带宽控制等特性，可被攻击者利用来伪造或篡改 IP 包、监听、拒绝服务等攻击。」注意标准答案比 PPT 多了「无连接」一条——无连接意味着 IP 不维护任何状态，攻击者可以在任何时刻插入、记录、重放分组。

全章因果链：一根绳串起三层

这一章看上去很散——上来讲网卡混杂模式，中间讲 ARP 和 NAT，最后一大半讲 IPSec。实际上它是一条自下而上的链：每一层都发现自己堵不住某类洞，只好把责任往上推，一路推到 IPSec 才算收口。把这根绳记住，比背任何表格都管用。

起点 · 物理层与数据链路层PPT p.3–12

网卡可以设成混杂模式，把不发给自己的帧也全收下来。MAC 地址可以随便改。结论：同一个局域网里，「谁都能看见谁」是硬件层面的默认状态，不是漏洞。

↓ 那就在链路层加认证吧
① 链路层的补丁：静态表 + CHAPPPT p.13–16

做法：硬编码 MAC 白名单；用 CHAP 做挑战/响应认证（不传口令，传散列值）。

留下的坑：静态表在大型动态网络里根本维护不了；CHAP 认证完之后连接期间不做任何验证或加密——认证过的通道，后面照样能被劫持。而且这些手段只保护一段链路，出了这个局域网就没了。

↓ 责任推给网络层
② 网络层自己也不设防PPT p.35–53

发现的问题：路由表可以被中毒、被淹没；IP 地址可以冲突、被拦截；IP 无状态所以能重放；分段机制能被用来耗内存和绕过检查。

PPT p.46 原文点破了根子：「大部分网络层协议没有实施身份鉴别、验证及保护网络数据，假设安全预防措施由高层协议实施」。——网络层把责任推给了上层，上层却未必接。

↓ 先用「工程手段」凑合一下
③ IP 安全可选方案：躲、挡、藏PPT p.54–66

做法：禁用 ICMP、用私网地址、上 NAT / RNAT、IP 过滤与出口过滤。

这些都不是密码学，是「让攻击者够不着」。NAT 提供匿名和隐私，防火墙按地址挡。留下的坑：一旦攻击者进得来，或者数据要跨公网走，这些手段一点用都没有——因为数据本身仍然是明文、仍然无法证明来源。

↓ 只能上密码学了
④ IPSec：把认证和加密做进 IP 层PPT p.68–145（78 页 · 全章 54%）

做法：AH 管完整性 / 来源认证 / 抗重放；ESP 在此之上再管加密；IKE 管密钥怎么协商出来；SA 把「用哪个协议、哪个模式、哪把密钥」打包记下来；SPD 决定哪些流量要保护。

为什么做在 IP 层？因为 IP 层之下的链路层只能保一段，IP 层之上的应用层要一个个改。做在 IP 层，对上层协议和终端用户都是透明的——不用改一行应用代码。这就是课本 p.185 那四条优点的由来。

↓ 但 IPSec 只保护「数据包」，保护不了「路怎么走」
⑤ 路由安全：包是真的，路是假的课本 p.188–196

IPSec 能保证包没被改、来源可信。但它管不了路由协议本身被骗——RIP 明文可伪造、OSPF 序列号可被抢、BGP 无条件信任对等系统的通告，于是有了 BGP 路由劫持和「数字大炮」。这是 IPSec 之外的另一条战线。

✗ 课本 p.162 图 6-2 画的

IPSec 安全体系 → AH / ESP → 加密算法 / 认证算法 → 汇到 DOI → 再往下挂 密钥管理（IKE）。

问题：这个画法把 DOI 画成了「算法之下、IKE 之上」的一个中间层，暗示 IKE 从属于 DOI，也暗示 DOI 只跟算法有关。

✓ PPT p.74 老师给的

IPSec 安全体系之下并列挂六项：AH 协议（RFC 2402）、ESP 协议（RFC 2406）、加密算法、验证算法、DOI、密钥管理（IKE 协议）（RFC 2409），体系本身是 RFC 2401。

为什么这样才对：DOI 和 IKE 是平级的两个独立组成部分。DOI 是「命名与解释的约定」（负载格式、交换类型、算法命名），IKE 是「密钥协商协议」，谁也不从属于谁——IKE 在协商时引用 DOI 的命名，但不是 DOI 的下级。

怎么记：PPT p.75 单独用一整页解释 DOI，说 「DOI 标识用来说明 payload 通过哪一个 DOI 来解释」，常用的两个值是 0（ISAKMP DOI）和 1（IPSec DOI）。DOI 是个「用哪本词典查」的标签，不是协议栈里的一层。

更正二 · PPT 第 99 页 PPT p.99

这一页贴的是传输模式/隧道模式的认证范围图，老师在图上补了两行红字：

✓ 传输模式（AH）

「更正：认证整个分组，除了 IP 首部的可变字段」

✓ 隧道模式（AH）

「更正：认证整个分组，除了外部 IP 首部的可变字段」

老师在纠什么？很多图为了省事，把 AH 的认证范围画成「只盖 IP 载荷」或者「盖整个包」——两种都不准。准确的说法只有一句：AH 认证的是整个 IP 包，但 IP 首部里那几个「路上本来就会变」的字段要先临时置 0 再算。

哪几个字段？课本 p.169 + PPT p.119 服务类型 ToS、标志 Flag、片偏移、TTL、首部检验和、选项字段。理由很直白：TTL 每过一跳就减 1，首部检验和跟着重算，你要是把它们算进 ICV，包还没到目的地就「认证失败」了。

这条会怎么考：习题选择第 7、8、11、12 题问的正是「AH 传输/隧道模式 SA 的认证对象包括什么」，四个选项里就藏着「仅 IP 载荷」「仅 IP 首部」这些陷阱。正确答案永远带着「IP 首部的选中部分」这个词——「选中部分」就是「去掉可变字段之后剩下的」。

承上
第 0 节说 IP 没有认证、没有加密。但那是网络层的事。在网络层之下，还有一层——数据链路层，它离硬件最近。
本节

1.1 混杂模式：网卡为什么能偷看PPT p.3–6

PPT 第 3 页 · 问题

一块网卡凭什么能收到不是发给自己的数据？

正常情况下不能。PPT p.3 原文：「正常模式下，网络寻址机制（MAC）能阻止上面的堆栈接收非指向该结点的数据。」网卡收到一个帧，先看目的 MAC 是不是自己，不是就丢掉，连往上送都不送。

问题出在「但是」后面那半句：「但很多网络接口（网卡）支持无地址过滤，运行在混杂模式的节点能接收所有报文帧，允许攻击者接收所有来自网络的数据。」

关键：这不是漏洞，是设计出来的功能

混杂模式（promiscuous mode，PPT 也叫「随意模式」）本来是给网络分析和查错用的——你要抓包排障，就必须能看见别人的包。攻击者只是用了同一个开关。所以这个「洞」补不掉：它就是网卡的正常能力。

PPT p.3 列了攻击者由此能拿到什么：明文传送的数据、网上的系统数量和类型、通信类型、网络活动时间。最后一句最阴：「攻击者可得到预警信号，它的存在是否被检测到」——他一边偷听，一边能听见你在不在查他。

三个「模式转换工具」PPT p.4–6

PPT 花了三整页分别介绍三个工具。它们的共同点是：都要把网卡设成混杂模式。考试如果考，多半是问「哪个是什么」，记住各自的一句话定位就够：

PPT 强调的两点：① 运行必须有 root 权限；② 它「通过将网络接口设置为混杂模式，绕过标准 TCP/IP 堆栈进行工作」。支持针对网络层、协议、主机、网络或端口的过滤。

2SnortPPT p.5

轻便的网络入侵检测系统（IDS），能做实时流量分析、协议分析、内容查找/匹配。

· 封包纪录模式 packet logger —— 抓包存到硬盘

1.2 ★ 检测混杂模式的三种办法PPT p.7–8

PPT 第 7 页 · 问题

混杂模式是被动收听、不发任何包，那怎么可能发现有人在偷听？

这是本节最漂亮的一段推理，PPT 原文已经把逻辑写全了：「混杂模式将所有接收到的数据送到网络层及其高层处理，由于很多高层协议假设网络数据在底层已经被检验过，如果分组内的数据要求作出回答，高层协议可以回答：如 ARP、ICMP 和 DNS，这为混杂模式检测提供可能。」

把这段话拆开：破绽在「分工」上

正常网卡：链路层先过滤 → 不是我的，丢掉 → 高层根本看不到。
混杂模式：链路层不过滤 → 全部送上去 → 高层协议以为「能到我这儿的一定是给我的」，于是照常回答。
——偷听者的网卡是哑的，但他的操作系统不是。你构造一个「链路层该拦下、但网络层看了会想回话」的包，谁回话谁就露馅。

A用 ARP 检测PPT p.7

做法：发一个硬件地址无效、但 IP 地址有效的 ARP 分组。

正常主机：先查 MAC，发现不是自己 → 数据链路层直接拒绝该分组，没有任何反应。

混杂主机：分组被收下并上送 → ARP 模块看到 IP 是自己的 → 产生一个 ARP 响应。谁回了，谁就开着混杂模式。

B用 ICMP 检测PPT p.8

做法：连发多个 ICMP 回答分组（ping），比较延迟。

正常主机：多个 ICMP 分组「应该产生多个具有相似延迟的回答」。

混杂主机：「结点接收并处理多个分组，因此有更大的延迟」——因为它还得处理网上所有其他人的流量，CPU 忙。这是一种旁路（时间）检测，不如 ARP 法确定。

C用 DNS 检测PPT p.8

做法：监控 DNS 请求，看谁在做大量反向解析。

原理：「很多分组捕获工具都是根据捕获到的 IP 地址查找主机名（反向地址解析）」。抓包工具为了把 IP 显示成好看的域名，会主动去查 DNS。——它不是被网络诱骗露馅的，是自己的「贴心功能」出卖了自己。

★ 三种办法各自靠什么，别记混

ARP 法靠的是链路层与网络层的过滤职责错位（最硬，能直接确定是哪台）；ICMP 法靠的是处理负载造成的时间差（旁路，只能怀疑）；DNS 法靠的是抓包工具自己的反向解析行为（针对的是工具，不是网卡）。一句话串起来：一个骗网卡，一个测负载，一个抓工具的习惯。

1.3 另外五类风险PPT p.9–12

混杂模式讲了 6 页，剩下五类风险 PPT 各给了半页到一页。它们的共同逻辑：数据链路层是一个「软件层」，任何帧都要消耗 CPU。

2负载攻击PPT p.9

PPT 点破了根子：「数据链路层是一个软件层，这意味着需要处理器来处理每个分组。」

攻击方式：「在多主机网络，每个主机接收每个广播帧，这些帧必须经过数据链路层，在该层以及高层进行处理」。广播是免费群发——攻击者发一份，全网每台机器都得付出 CPU。地址过滤开销很低，但高层处理很贵，所以攻击会明显抬高 CPU 负载。

3地址攻击PPT p.10

「大部分地址机制允许一个结点改变有效的 MAC 地址，配置相同 MAC 地址的结点将被拒绝网络连接。」

和混杂模式的配合：攻击者先在混杂模式下观察网络帧，识别出哪些 MAC 是被接受的，再把自己改成那个合法地址。——偷看是为了伪装，两个能力是连着用的。

4帧外数据PPT p.10

「不包含在报文帧内的数据通常被丢弃，但这样的信息能在物理层传输。」运行在混杂模式的网络接口可以接收帧外数据。

但这依赖硬件：PPT 明确写了「100Base-T 以太网网卡可获取帧内和帧外数据，但无线网卡通常将帧外数据作为噪声丢掉」。这个「有线能、无线不能」的对比是个考点。

5DHCP 耗竭PPT p.11

两步走，很典型：

① 耗光：「通过利用伪造的 MAC 地址来广播 DHCP 请求」，请求足够多就能「耗竭向 DHCP 服务器所提供的地址空间」。
② 顶替：然后「在自己的系统中建立起虚假的 DHCP 服务器来对网络上客户发出的新 DHCP 请求作出反应」。真服务器没地址可发了，假服务器就成了唯一的那个。

6物理风险PPT p.12

四条递进：能直接访问数据链路报文帧 → 能窃听所有链路通信 → 能记录和回答（重放），而且「回答数据能被数据链路层接收」→ 能用插入攻击生成带有效链路帧的负载攻击。物理接触打穿一切链路层防护，这也是为什么后面要靠密码学而不是靠管控。

1.4 四条缓解办法PPT p.13–16

1硬编码PPT p.13

针对：中间人攻击（拦截）和伪造 MAC 地址（重指硬件地址）。

做法：「采用静态地址表阻止非授权连接」。例子：拨号服务器只接受与存储的呼叫者 ID 表相匹配的呼叫；无线 AP 设置 MAC 过滤。

PPT 自己说了局限：「对大型动态网络未必可行」——几千台设备手工维护一张表，做不到。

2CHAP 挑战握手认证PPT p.14

全称：The Challenge Handshake Authentication Protocol，使用共享密钥对初始连接进行身份鉴别。

三步：① 认证者先发一个随机挑战信息给对方；② 接收方用挑战信息 + 共享密钥经单向 HASH 函数算出响应值发回；③ 认证者做相同的计算，比对一致性。

★ PPT 明写的缺点（易考）：「连接建立后不执行任何验证或加密」。而且它可以在连接建立后的任何时刻重新使用——但那是可选的，不是自动的。

3PAP 口令认证PPT p.15

「比 CHAP 简单得多」：登录凭证（ID 和口令）用明文从客户端传到服务器。

三条要命处，PPT 一句话全列了：「容易被监听而泄漏」「没有加密」「对拦截和回答（重放）攻击没有保护」。PAP 和 CHAP 的对比是标准考点：一个传口令本身，一个传口令的散列响应。

4高层身份鉴别 + 分析工具PPT p.16

高层鉴别：「依赖高层协议时保护数据链路层是最普遍的方法」——但 PPT 紧接着泼冷水：「高层协议有可能不提供安全机制，或提供弱的安全方案，只有少数高层协议对数据链路层进行身份鉴别」。

分析工具：tcpdump、Snort、Ethereal。——注意这个反转：同一批工具，1.1 节里是攻击手段，这里是防御手段。区别只在谁在用。

★ 这四条为什么最终都不够用（承接下一节）

PPT p.48 后面有一句话，正好回头总结了这一节：「虽然数据链路层具有身份鉴别和加密隧道的安全，诸如 CHAP 或 VPN，但它们仅仅保护数据链路连接。敌意的网络通信能进入数据链路隧道，和正常的网络层通信一样得到允许和保护。」
翻译：链路层的隧道是「一条加密的管子」，它保证管子里的东西没人偷看，但它不检查往管子里塞的是什么。坏包进了管子，照样被安全地送到对面。——这就是必须在网络层再做一层的根本原因。

1.5 MAC 的三类风险PPT p.17–23

PPT p.17 开宗明义：「攻击者可以利用 MAC 信息来侦察、伪装和基于负载的攻击。」——三类，正好对应三个小节。

① 硬件框架（profiling）攻击 —— 侦察PPT p.17–18

先记住 MAC 地址的结构

「MAC 地址 48 位，表示为 12 个 16 进制数，如：08:00:20:0A:8C:6D，其中前 6 位 16 进制数代表网络硬件制造商的编号，它由 IEEE 分配，而后 6 位 16 进制数代表网络产品（如网卡）的系列号。」

攻击者拿它干什么：「侦听到前 6 位可以在一定程度上判断设备类型甚至操作系统」。——这就是「侦察」：还没碰你，就先知道你用的是什么牌子的设备。

MAC 地址能不能改？能，而且有两种改法PPT p.18——这个对比 PPT 专门列了出来：

永烧 EEPROM（永久改变）

「利用网卡厂家提供的修改程序来烧录网卡的 EEPROM，这样做虽然可行，但是风险很大、操作也复杂」。

临改注册表（临时改变）

「通过软件或者系统自带的功能修改注册表中的 MAC 地址」。这才是实际用的那种——重启就还原，查都不好查。

② 伪装攻击 —— 把自己改成别人PPT p.19–22

「攻击者把自己的 MAC 地址修改成与网上另外一台电脑相同的 MAC 地址，这样两者就会互相干扰，造成 DoS 攻击。」PPT 接着分三种情况讨论结果，这三条很细，是典型的选择题素材：

★ PPT p.21 / p.22 两张图：MAC 冲突 vs IP 冲突

老师用两整页画了两张对照图，讲的是同一个网络里两台机器「撞车」时，交换机和路由器各自会乱成什么样。这两张图不复现像素，用表格说清它们展示的事实就够：

PPT p.21 · MAC 地址相同

两台机器 IP 不同（192.168.0.2 / 192.168.0.3），MAC 都是 0003.E414.A080。

  • 路由器 ARP 表：两个 IP 都指向同一个 MAC——表面上「正常」，实际无法区分
  • 交换机端口映射表：E0 记着这个 MAC，E1 就成了「?」——同一个 MAC 不可能同时挂在两个端口上，表来回抖动
PPT p.22 · IP 地址相同

两台机器 IP 都是 192.168.0.2，MAC 不同（0003.1111.1111 / 0003.2222.2222）。

  • 交换机端口映射表：E0 和 E1 各记各的 MAC，交换机毫无察觉——它只认 MAC，不看 IP
  • 路由器 ARP 表：这个 IP 要么映射到 1111，或要么映射到 2222——谁的应答最后到，就听谁的

两张图放一起要看出的东西：交换机只认 MAC，路由器（的 ARP 表）负责 IP↔MAC。所以 MAC 冲突把交换机搞乱，IP 冲突把 ARP 表搞乱。这也解释了 2.3 节要讲的「地址拦截」——谁的应答更快、更晚，谁就赢。

③ 负载攻击 —— 用广播位放大PPT p.23

一个比特换全网 CPU

「MAC 的第一个八位包含地址标志，最低位指示多播分组，奇数值标识多播 01-00-00-00-00-00，FF-FF-FF-FF-FF-FF 表示广播。」

攻击者可以把 MAC 地址改成多播或者广播来发起负载攻击——PPT 那句评价最到位：「对攻击者自身毫无影响，但网上其他节点将处理攻击者发来的每个分组」。发一份，全网每台机器都得处理一份，这就是「放大」的原型。后面 2.5 节讲的 ICMP 分组风暴/放大攻击，用的是同一个思路，只是搬到了网络层。

1.6 ARP / RARP 的风险PPT p.24–31

PPT 第 24 页 · 先把 ARP 是什么讲清

机器只知道对方的 IP，怎么知道该往哪个 MAC 发？

靠喊。ARP 就是在局域网里广播一句「谁是 192.168.0.5？请告诉我你的 MAC」，然后等回话。PPT p.24 四句话讲完了全部机制：

PPT p.24 原文四条
  • ARP 查找与 IP 地址对应的主机的 MAC 地址；RARP 是查找与 MAC 地址所对应的主机的 IP 地址（方向相反，别记反）
  • ARP 和 RARP 请求是广播分组，只有一个对应的节点回答报文给询问主机
  • 查询结果存储在一张 ARP 表中（缓存，避免每次都问）
  • ★ ARP 攻击仅限于本地——「ARP 分组并不通过网桥、路由器和网关」

最后一条是这一整节的边界条件：ARP 投毒只能在同一个广播域里干，攻击者必须已经在你的局域网内。这也是为什么它常常是「第二步」——先蹭上 WiFi，再投毒。

ARP 损坏及其影响PPT p.26–28

PPT p.26 定义了什么叫「损坏」：「当一个无效的或不经意的差错进入 ARP 表，会造成系统 ARP 表受损」。注意「不经意」这个词——ARP 表出问题不一定是攻击，也可能是配置错误，但后果一样。

A把表填满（资源耗尽）PPT p.26

「ARP 缓存条目数量是有限的，大量的假的 ARP 条目会填满 ARP 表」，然后二选一，两条路都是坏的：

· 忽略新的 ARP → 「局域网上新的节点不能再联络」
· 丢掉老的 ARP 条目 → 「网络性能会变慢，因为对每个系统要发送的分组都需要 ARP 查询」

B重写已有条目PPT p.27–28

DoS 攻击：「新的 ARP 回答对 ARP 表中旧的 ARP 记录重写，如果用一个坏的 MAC 地址来重写，那么将来连接到重写的节点的 IP 地址将失败，因为它被送到错误的 MAC 地址。」——包发出去了，只是发到了不存在的地方。

MitM 攻击：「ARP 表的条目用不同机器的 MAC 地址重写，这样新的节点将接受所有指向原来结点的所有通信」——同样是重写，填「垃圾 MAC」是 DoS，填「攻击者自己的 MAC」就是中间人。区别只在填什么。

★ 实验台：ARP 投毒 → DoS / MitM

上面那句「填垃圾是 DoS、填自己是 MitM」是本节最值钱的一句话。下面这个实验台让你亲手改一次 ARP 表，看三台机器各自的表变成什么样、包最后走到哪儿。

实验台 ARP 缓存投毒 PPT p.27–31 · 三张表实时联动

缓解 ARP 受损的四种办法PPT p.29–31

这四条 PPT 用了三页讲，而且每一条都明确写了「挡得住什么、挡不住什么」。考简答题时，能说出局限比能背出名字值钱：

ARP 应答		 「并非每个 ARP 应答必须插入 ARP 表。Linux 和 BSD 仅对本地主机送来的 ARP 请求缓存条目，这可阻止未经请求的 ARP 回答进入 ARP 表。但 Windows 操作系统接受未经请求的 ARP 回答并加入 ARP 表。」 ★ 关键的半句：「虽然 ARP 回答过滤能阻止未经请求的条目，但它并不阻止来自重写已有条目的新的回答」。——挡住了「凭空冒出来的」，挡不住「冒充回答你刚问的那个」。
④ 锁住
ARP 表		 「ARP 表能暂时锁住，一个已经建立的连接能在短期内锁住 ARP 表条目。锁住期间 ARP 回答不能重写已经锁住的条目。」 「以确保已经建立的连接不能改变，从而缓解 MitM 攻击」。
注意是「缓解」不是「消除」：锁的是已建立的连接，新建的连接仍在窗口期内。
★ 四条办法的一句话记忆

钉死（静态表）、放过期（限时）、挑着收（过滤）、锁一会（锁表）。其中只有 ① 是真正的解决，② 只治「填满」，③ 只治「凭空冒出」，④ 只治「已建立的连接」。PPT 之所以逐条写清局限，就是在说：链路层这一层根本补不干净——这正是要往上走到网络层和 IPSec 的理由。

没有内容完整性认证：攻击者可以「在通信线路上非法窃取 IP 包，修改各个字段的内容，并重新计算检验和，而接收方无法判断该包是否被篡改过」

后果链：没有报文源认证 → IP 源地址假冒 → 以此为基础实施拒绝服务、中间人、源路由、客户端、服务器等攻击。

「IPv4 报文没有使用加密机制，因此攻击者很容易窃听到 IP 数据包并提取出其中的应用数据」

不只是数据泄露：「攻击者还可以提取出数据报中的寻址信息以及协议选项信息，进而获得部分网络拓扑信息；记录路由或时间戳的协议选项还可被攻击者用于网络侦察」。——首部本身就是情报。

★ 检验和为什么防不住人（这句最容易被忽略）

很多同学看到「首部检验和」就以为 IP 有完整性保护。没有。检验和是一个公开算法、无密钥的简单求和——任何人改完内容都能把它重算一遍。它防的是线路噪声导致的随机比特翻转，不是有意的篡改。
这正是第 3 章「散列 vs MAC」那条因果链在网络层的重演：无密钥的校验值只能防错，防不了坏。要防坏就必须引入密钥 → 这就是 AH 用 HMAC 的理由。

2.2 路由风险五类PPT p.35–39

先划清边界

这里讲的是通用的攻击分类，不涉及 RIP / OSPF / BGP 任何具体协议。课本 6.4 节讲的那三个协议在第 11 节。两边名字像，内容完全不同，别混。

PPT p.35 开头一句列全了五类：「针对路由器的攻击方式：直接攻击、表中毒、表淹没、度量攻击以及路由器环路攻击」。

1直接路由器攻击PPT p.35

DoS：「阻止路由器执行基本任务，使网络不能有效地连接，大部分基于负载攻击」——在特定端口流量太高，导致路由器无法管理通信，包括来自其他网络接口的通信（打一个口，全机瘫）。

系统破坏：路由器被控后可以「转发通信到不同的主机或网络、阻断来自特定主机的通信、或任意分配新的子网」。PPT 强调后果范围：「因为路由器扩展多个子网，受损的路由器会影响连接到它的每个网络的完整性和隐私性」。

2路由表中毒PPT p.36

「伪造的或受损的网络通信能重写、插入或移除路由表的条目，其结果和受损路由器几乎是一样的。」

为什么动态路由天生易受攻击（PPT 给了两条理由）：
· 新节点可能生成中毒数据
· 很少动态节点是可以验证的

PPT 给的对策：「关键路由器应使用静态路由表以防止中毒」。——又是「静态表」，和链路层的思路一模一样。

3路由表淹没PPT p.37

「路由器通常路由表容量有限」，攻击者「生成假的数据让路由器生成路由表」，表满之后三种处置，条条有害：

· 忽略新的路由：攻击者无法清除已建立的条目，但阻止了新的有效条目插入
· 清除旧的路由：「使用大的淹没攻击能将已建立的条目都清除」
· 清除最坏路由：「可使一些本来理想的路由被删除」
对策同上：关键路由应设置成静态。

4路由度量攻击PPT p.38

「使路由表的动态度量中毒。这种攻击可使一些好的路由成为不期望的路由。」

PPT 给的具体例子：「网络层协议支持质量服务 QoS 分组，采用流控决定连接质量。攻击者可伪造 QoS 分组来修改动态度量，结果是更慢的吞吐量、更长的路径和更昂贵的网络开销。」

对策：「固定路径应使用静态度量。对动态度量是关键的网络，应使路由器能经常检查期望的路由」。

5路由器环路攻击PPT p.39

这一条最巧妙，是「利用防御机制本身来攻击」。

正常机制：路由环路会引起过多带宽消耗，「很多协议企图检测和阻止路由环路，如 BGP 和 RIP」。「当路由器识别了一个路由环路，就将该路径从路由表中移除」。

攻击：「环路攻击者产生一个假的应答给环路检查，使路由器误认为发生了路由环路，结果一个理想的网络路径被移除。」
★ PPT 特意补的一句：「虽然静态度量能阻止度量攻击，但环路攻击仍能切除预期的路径」——前四条的万能解药「改成静态」，到第五条失效了。

2.3 地址机制风险与 DHCPPPT p.40–42

PPT 第 40 页 · 根子

两台机器抢同一个 IP，网络凭什么判定谁是真的？

判定不了。PPT p.40 第一句就是判决：「网络层并未定义对地址的身份鉴别和验证。」

于是有两类后果

① 假地址 —— 「当两个结点有相同的 IP 地址会产生冲突，假地址能阻止结点接收分组，导致网络连接中断」。这是破坏型的。

② 地址拦截 —— 这是窃取型的，而且规则很具体：「响应快的结点能维持网络连接，如果一个结点一直响应慢，则它的网络通信被锁住」。

把「响应快者赢」这条规则和攻击者的能力叠加，就得到 PPT 那句最狠的推论：

「具有快的结点的攻击者可以在混杂模式下观察网络通信，假如和另外一个结点具有相同的网络地址，则可拦截已建立的连接。最坏的情况是，将自己的 IP 地址配置成和路由器本地 IP 地址相同，则可阻止网上所有结点和该路由器通信。」
——注意这里又用上了混杂模式。第 1 节那个「偷看能力」在这里变成了「拦截能力」的前提。

DHCP 的两类攻击PPT p.41–42

PPT p.41 用一整页贴了 DHCP 的四步交互图（Discover → Offer → Request → ACK），p.42 讲攻击。DHCP 的根本问题和 ARP 一样：客户端无法验证「回答我的这个服务器是不是真的」。

A假释放攻击PPT p.42

正常机制：「DHCP 提供地址再分配办法，当一个结点不需要 IP 地址时，可以通知 DHCP 服务器收回该地址，并可分配给其他节点使用。」

攻击：「攻击者伪装一个已分配的地址，并释放它。DHCP 可能将该地址分配给其它主机，导致受害节点可能使用一个已经分配的地址。」
——攻击者替受害者「退租」，然后同一间房被租给了第二个人。结果就是 2.3 节开头那个 IP 冲突。

B假的动态分配PPT p.42

攻击：「攻击者可以配置自己的分配服务器，并且分配请求响应比原来的分配更快。」——又是「快者赢」。

★ 为什么这个比假释放严重得多：「分配响应包括一系列信息，例如 DHCP 提供一个 IP 地址、子网掩码、默认网关和 DNS 服务器信息，攻击者能提供假的信息给新的节点，并建立一个基于网络路由器的 MitM 攻击。」
——把「默认网关」改成攻击者的地址，受害者所有出网流量都会主动送到攻击者手上。这比 ARP 投毒更彻底，因为受害者是自愿的。

★ 一条贯穿三节的主线：「谁快谁赢」

ARP 应答（1.6 节）、IP 地址拦截（2.3 节）、DHCP 假分配（2.3 节）——这三处的胜负规则都是「先到／更快的那个说了算」，因为协议本身没有任何机制去判断哪个回答是真的。
攻击者不需要「骗过验证」，因为根本没有验证；他只需要「抢答」。这就是为什么这三类攻击都极其廉价，也是为什么真正的解法只能是密码学——让「真」这件事可以被证明，而不是靠先来后到。

2.4 分段风险与服务质量PPT p.43–45

1丢失分段攻击PPT p.43

机制根源：「一个大的分组要等接收到全部分段才能处理，每个接收的分段必须保存在分配给堆栈的内存中。」

攻击：「发生在当一个大的分组分段时，有一个分段永远未传递。导致堆栈被长期占用，进而消耗内存资源。」——发 99 个分片，永远不发第 100 个，接收方就得一直攥着那 99 个等。

两条对策（PPT 明说「能有效缓解」）：① 设置分段超时值；② 「大部分系统分配一个最大内存大小用于分段组装，假如分段数据总量大于最大分配内存，分段被丢弃」。

2分段重组攻击PPT p.44

「分段须标识以说明分段的次序」，两种情况导致潜在攻击：

· 分段重复：同样的分段 ID 出现两次以上
· 分段覆盖：重复的分段包含不同数据（这才是真正危险的那个）

三种解决办法：① 忽略第二次以后重复分段；② 在第一次分段上重写；③ 清除所有分段。
★ 为什么危险：不同操作系统选了不同策略。攻击者可以构造一组分片，让防火墙按 ① 重组出「无害」的内容，让目标主机按 ② 重组出「有害」的内容——同一串字节，两边看到的不是同一个东西。这就是 2.5 节「分段攻击」能绕过检查的原理。

3服务质量 QoSPPT p.45

根源同上：「网络节点无法区分真的 QoS 分组和伪造的分组，攻击者可以利用 QoS 功能来拦截通信。」

做法：「假的分组可以请求一个结点降低速率或发送更小的分组，降低通信性能。」——不用打垮你，只要让你「自愿」变慢。

4DDoS 反射PPT p.45

PPT 在 QoS 那页顺带给了 DDoS 的经典形态，这段值得逐字记：

「一个主机能生成很多回应（echo）请求，发送到网上很多主机，每个回应请求指定一个伪造发送者——DDoS 的目标。其结果是回应应答炸弹送至目标结点，足够大的攻击能摧垮网络。」
——攻击者一份都不用发给受害者。他发给一万台无辜主机，让它们「礼貌地回复」受害者。这就是反射型 DDoS，成立的唯一前提是：源地址可以伪造（缺陷 ①）。

2.5 IP 风险六类PPT p.50–53

PPT p.50 一句话列全：「IP 风险包括地址冲突、拦截、回答攻击、分组风暴以及转换通道、分段攻击」。前两条和 2.3 节有重叠，但角度不同——2.3 节问「为什么能」，这里问「具体怎么样」。

风险PPT 说了什么
1 地址冲突p.50 「在正跟 Internet 上两个结点不能共享相同的公网地址」。同一子网上两个结点 IP 相同时路由有两种可能：
· 不用交换机：「机器响应较快的会锁住较慢的系统，因为 IP 只跟踪第一个接收的分组」
· 用了交换机，结论反过来：「慢的系统会锁住快的系统。交换机的 ARP 表被较慢的主机发送的分组破坏，它将所有的通信指向较慢的节点」
★ 这个「反转」极易考：有没有交换机，赢家是相反的。原因是交换机的表被最后一个到达的帧刷新，而 IP 只认第一个到达的包。
2 IP 拦截p.51 「一个结点假装为另一个结点的 IP 地址」，PPT 明确分了三种方法：
① 攻击者用未在用的地址拦截，不会发生冲突（最隐蔽）
② 重新指向拦截：攻击者能重指网络连接到其他主机
③ 随意拦截：「只要攻击者位于源节点和目的节点之间的通路上，沿着网络通路的一个结点能拦截和响应 IP 分组」（这就是中间人的位置要求）
3 回答攻击p.51 「IP 是一种无状态协议，这意味着攻击者可以在任何时间记录和回答分组。」
★ 后半句才是关键：「虽然高层协议可以识别和拒绝 IP 内容，但IP 数据仍然是有效的」——上层能看出重复，但 IP 层照收不误，资源已经被消耗掉了。这就是为什么抗重放必须做在 IP 层，也就是 AH/ESP 的序列号。
4 分组风暴p.52 两类，成因不同：
· 放大攻击：「一个分组请求能产生一系列的回答，当 ICMP 请求一个广播地址，就能产生大量的回答」
· ICMP 差错处理不当：「RFC 1812 中有各种规定以防止这类分组风暴，用户违反指南可能产生很多 ICMP 差错，并淹没网络，如果两个这样的节点存在就会互相放大差错，最后消耗掉所有可用带宽」
（RFC 1812 这个编号是个容易出选择题的细节）
5 分段攻击p.53 「IP 将大的数据分段传输，并在接收端重新组装，分段攻击修改 IP 分段的报头所包含的信息来实现自己的攻击，破坏重组。」——接 2.4 节：改的是片偏移和 MF 标志这些「组装说明书」，不是数据本身。
6 转换通道p.53 「很多防火墙和 IDS 在中继通信前只是对 ICMP 报头执行基本检查，并不详细检查 ICMP 分组内容，因此 ICMP 能不经检查通过某些防火墙和 IDS 系统，这使 ICMP 成为转换信息的理想工具。」
——把要外传的数据塞进 ping 包的载荷里。防火墙看见的是「一个普通的 ping」，实际上是一条隧道。这直接引出 3.1 节的第一条对策：禁用 ICMP。

网络层安全：为什么必须靠专门的协议PPT p.46–49

PPT p.46–49 用四页做了个小结，它其实就是第 3 节（工程手段）和第 4 节（IPSec）的目录。这四页里最值钱的是 p.47 那句对「校验和」的判决：

PPT p.47 原文

「网络层并不定义安全预防方法，安全由某些专门的网络协议解决，像 IP、IPX 这些通用协议只提供简单的校验和，虽然能检测某些数据差错，但对检测攻击者没多大作用。」

「IPv6 和 IPSec 是两个著名的安全协议。IPSec 是 IP 协议的扩展，是附加在 IP 上的面向安全的协议，包括身份鉴别报头、数据封装及密钥交换方法（——正好是 AH、ESP、IKE 三样）。IPv6 除了 IP 地址扩展，也包括加密的身份鉴别和数据封装。」

2网络不兼容能力PPT p.48

一个反直觉的观点：不兼容本身可以当安全用。「从 IP 转换到 IPX 会使网络无法实施 WEB 浏览、电子邮件和其他面向网络的工具」。但代价立刻显现：「虽然 IPv6 支持数据加密，但很多高层协议和应用不支持 IPv6」。

3体系结构PPT p.48

「物理网络拓扑提供某些内在的安全特点，限制访问物理层可减少窃听、拦截、回答攻击的风险。」
但紧接着就是第 1 节末尾引过的那句判决：链路层隧道（CHAP / VPN）「仅仅保护数据链路连接」，敌意通信进了隧道照样被保护。

安全过滤：基于 IP 地址过滤能缓解某些身份鉴别问题，但 PPT 自己评价得很低——「这些安全方法是在模糊安全水平」（security by obscurity）。

出口过滤的价值：「远程攻击者可以伪装不同的 IP 地址，但它们并不能接收和回答，除非它们在目标主机和伪装网络之间的路径上。」——伪造源地址容易，但收回信难。这是所有反欺骗过滤的理论基础。

找一个有公网地址的中间人替它跑腿。PPT p.56 原文：「NAT 是通过公共网关将来自内网的分组中继，NAT 网关是桥接 Internet 和内网的双主机系统，对于每个分组，NAT 服务器在内部中继表存储映射关系。」

★ 中继表的三部分（PPT p.56 原文，逐字要记）

「中继表是内部发起连接请求时建立的。中继表包含 3 部分：

  • 源 IP 地址和传输层端口

出去时：「使用 NAT 外部 IP 和端口号将分组中继到外部网络，外部主机视分组来自 NAT 服务器，而非内部主机。」
回来时PPT p.57：「它将分组目的地和内部中继表进行比较，然后将分组转发的内部源。」

NAT 的两个安全效果PPT p.57

匿匿名

「攻击者不能连到内部主机，与内部中继表条目不能匹配的分组都被丢弃。这使得 NAT 服务器成为有效的防火墙。」
★ 代价那一句 PPT 也写了：「NAT 服务器所支持的连接，必须是内部主机主动发起的」——这就是下一节 RNAT 存在的全部理由。

3.3 RNAT：为什么还要反着来一个PPT p.62

PPT 第 62 页 · 问题

NAT 挡住了所有外部发起的连接。那公司的网站怎么办？

PPT 把矛盾说得很直接：「因为 NAT 能阻止外部网络主机发起的连接，因此不能把 WEB、Email 等对外部网络提供的服务放在内网」。

这是一个「安全机制和业务需求正面冲突」的典型场景。NAT 的安全性完全来自「只认内部先发起的连接」，而 Web 服务器的工作恰恰是「等着外面来连」——两者不可能同时成立。

RNAT 的解法：开一个定向的、静态的口子

「RNAT 提供从 NAT 外部端口到内网上的 IP 地址和内部端口的静态映射，使用 RNAT，外部连接到 NAT 服务器的 80 端口能被路由到内网上的 WEB 服务器。」

★ PPT 最后那句话是整节的题眼：「NAT 提供防火墙功能，而 RNAT 允许面向服务的应用。」

两者的区别就是「表是谁建的」：NAT 的中继表是内部主机发起连接时动态建的，用完就没；RNAT 的映射是管理员事先静态配好的，一直存在。安全性正是在这里被有意让出去的——你开了 80 端口，就等于承认「这个口子任何人都能敲」。

3.4 IP 过滤与出口过滤PPT p.63–64

5IP 过滤PPT p.63

「大部分非 NAT 防火墙支持基于 IP 分组头的分组过滤，过滤规则能限制特定主机、子网或服务类型（TCP、UDP 或 ICMP）的分组。」

★ 分层的关键一句（易考）：「网络层防火墙只能看到 IP 报头，传输层防火墙才能过滤基于特定端口和服务的分组，传输层防火墙可用于限制访问 Web 或 E-mail 服务器。」
——想按「端口/服务」过滤，就必须做到传输层；只在网络层，你只有地址和协议号可用。

6出口过滤PPT p.64

「将防火墙规则应用到出口通信。最简单的出口过滤运行在网络层，以阻止来自内部网络的假的源地址分组。」

为什么这条特别重要：它不是保护自己，是防止自己成为别人的攻击源。回想 2.4 节的反射型 DDoS——它成立的前提是「攻击者能发出源地址伪造的包」。如果每个网络的出口都做这件事，反射攻击就无从谈起。
更复杂的出口过滤在高层：传输层限制端口，高层限制 DNS 和 LDAP 访问、VPN 和 SSL 身份鉴别、Web URL 访问、E-Mail/SPAM 过滤、病毒扫描等。

第 7 条 · IPSECPPT p.65

★ 这一页最值钱的是「粒度」那句：「身份鉴别可以基于网络层主机、子网、服务类型、传输层端口或应用层用户实施」——IPSec 虽然做在网络层，但它能按传输层端口甚至应用层用户来区分要不要保护。这正是第 4.4 节 SPD「选择符」的能力，也是课本表 6-1 那张主机 SPD 示例表能按 TCP/UDP 端口写规则的原因。

透明性那句是全章反复出现的卖点：「高层协议不需要提供自己的加密，也无需修改就可以用 IPsec，这使 IPSec 成为安全连接和 VPN 的理想解决方案。」

第 8 条 · IPv6PPT p.66

PPT 列的 IPv6 改进：扩大的地址空间；支持路由组播和广播分组；在网络层身份鉴别和加密连接的功能，且高层协议可在加密通道上使用而无须修改协议；支持封装以允许网络隧道；加密和身份鉴别机制，提供了完整的 VPN 解决方案。

✓ 从安全方面看：两者本质相同

「IPv6 和 IPSec 本质上是相同的，两者都提供强的身份鉴别、加密和 VPN 支持，很多 IPv6 和 IPSec 的特点都基于相同的 RFC 规范。」

✗ 从可行性看：差得远

「从 IPv4 转换到 IPv6，路由器和网络设备必须更新以支持 IPv6 协议；相反，任何支持 IPv4 的路由器也能支持 IPSec，仅需源和目的站支持，而无须中间系统支持。」

★ 这一组对比是标准的简答素材。一句话概括：安全能力上 IPv6 ≈ IPSec，但部署代价上 IPSec ≪ IPv6——因为 IPSec 是端到端的，中间路由器什么都不用改；IPv6 要求整条路径上的每台设备都换代。这也解释了课本 p.161 那句：「IPsec 最开始是为 IPv6 制定的标准，考虑到 IPv4 的应用仍然很广泛，所以在 IPsec 标准制定过程中也增加了对 IPv4 的支持。在 IPv6 中，IPsec 是必须支持的，但在 IPv4 中，则是可选的。」课本 p.161

★ 八条方案一句话串起来（速记）

① 关掉（禁 ICMP）→ ② 躲起来（私网地址）→ ③ 换脸（NAT）→ ④ 开小口（RNAT）→ ⑤ 挡进来的（IP 过滤）→ ⑥ 挡出去的（出口过滤）→ ⑦ 加密签名（IPSec）→ ⑧ 换协议（IPv6）
前六条是网络工程，让攻击者够不着；后两条是密码学，让攻击者够着了也没用。PPT 把 IPSec 放在第七条，然后立刻用剩下 78 页展开它——这个编排本身就说明了老师认为哪一条才是答案。

4.1 为什么需要 IPSec · 四大功能PPT p.68, 72–73

PPT 第 68 页 · 全节的问题页

为什么需要 IPSec？

PPT 自己在标题上就写了这个问句，答案分三段：

PPT p.68 原文
  • IP 协议安全性能差，存在众多安全隐患 —— 如窃听、篡改、伪造（IP 欺骗）、重放
  • IPSec（IP Security）：端到端的确保 IP 通信安全 —— 认证、加密及密钥管理
  • 为 IPv6 制定（必选），支持 IPv4（可选）

「窃听、篡改、伪造、重放」这四个词，正好对应 IPSec 的四样东西：窃听 → 加密（ESP）；篡改 → 完整性（HMAC/ICV）；伪造 → 数据源认证（带密钥的 HMAC）；重放 → 序列号 + 滑动窗口。记住这个一一对应，AH 和 ESP 各提供什么服务就不用死背了。

「端到端」三个字也要留意：它意味着中间的路由器不参与、也不需要理解 IPSec——这正是 3.5 节说的「IPSec 仅需源和目的站支持」。

IPSec 的四大功能PPT p.72–73

1作为隧道协议实现 VPN

「IPSec 作为第三层隧道协议，可以在网络层创建一个安全隧道，使两个异地私有网络连接起来，或者使公网上的计算机可以远程访问企业的私有网络。」
「第三层」这个定语要记：课本 p.184 给了完整的分层——二层隧道协议 PPTP / L2TP，三层隧道协议 GRE / IPsec，应用层隧道协议 SSL/TLS VPN。课本 p.184

2保证数据来源可靠

「IPSec 通信之前双方要先用 IKE 认证对方身份并协商密钥，成功之后才可以通信，第三方不可能知道验证和加密算法以及相关密钥，因此无法冒充。」
——注意这句话把 IKE 的地位点出来了：认证和协商发生在通信之前。IKE 不是可有可无的配件，是前置条件。

3保证数据完整性

「保证数据传送过程中任何篡改和丢失都能被检测」。注意是「被检测」不是「被阻止」——密码学能做的只有发现，不能阻止对方动手。

4保证数据机密性

PPT 这一条只有标题没有正文。它由 ESP 独家提供，AH 完全不提供——这是 AH 与 ESP 最根本的区别，也是习题第 3、4 题考的东西。

5.1 两种模式各保护什么PPT p.99–103

PPT 第 102 页 · 隐藏的问题

既然传输模式更省带宽，为什么还要发明隧道模式？

PPT p.102 给的理由不是「安全性更高」，而是一条硬性的工程约束，原文非常值得逐字读：

PPT p.102 原文

「如果路由器要为自己转发的数据包提供 IPSec 安全服务，必须使用隧道模式。路由器主要依靠检查 IP 头来做出路由选择，不会也不应该修改 IP 头部以外的其他内容，如果路由器对要转发的包插入传输模式的 AH 或者 ESP 头部，便违反了路由器的规则。」

把这段话讲透：传输模式做的事是「在原 IP 首部和 TCP 之间插一段」——这是在改造别人的包的内脏。路由器的职责是转发，它没有资格去改一个不属于它的包的内部结构。
隧道模式做的事完全不同：把原来那个包整个当成一坨数据，前面套一个全新的 IP 首部。——它没有动原包一根汗毛，只是把它装进了信封。这个动作路由器是有资格做的。

所以判据只有一条：只要 IPSec 双方有一方是安全网关或路由器，就必须使用隧道模式（PPT p.102 / 课本 p.166 都这么写）。反过来，传输模式「通常情况下只用于两台主机之间的通信」——因为只有终端主机才有权处置自己的包。

6.2 ★ 完整性检查与可变字段PPT p.118–120课本 p.169

ICV 的计算与验证过程（PPT p.118 原文）

「AH 的验证范围是整个 IP 包，过程如下：
在发送方，整个 IP 包和验证密钥作为输入，经过 HMAC 算法计算后得到的结果（ICV）被填充到 AH 的验证数据字段中；

★ 这段话就是习题简答第 3 题的骨架

课本习题简答第 3 题问的是「在 AH 协议中，并非 IP 首部中的所有字段均参与 MAC 的计算」，然后让你分别指明 IPv4 首部、IPv6 基本首部、IPv6 扩展首部里哪些字段是不变的、哪些是可变但可以预测的、哪些是随机的。
你的书上在这道题旁边写了：「(IP包 + 认证密钥) HMAC 验证算法 → AH 首部　AH 完整性认证过程」——那正是上面这段的浓缩。下面把三类字段分清。

✗可变字段 —— 计算时临时置 0

PPT p.119 逐条给了理由：

ToS
「8 位服务类型字段指出延时、吞吐量、可靠性方面的要求。某些服务器会修改此字段以达到特定的服务质量」
标志字段
「用于标识分段的 3 位标识：DF（不分段）、MF（更多分段）和 0」

分片位置，重新分片就会变
TTL
每过一跳减 1

「中间路由器对 IP 头部的任何修改都要重新计算头部校验和，因此可变」

记录路由、时间戳等，路上会被追加

★ 课本补的一句常被忽略：「另外，AH 首部的认证数据字段在计算之前也要用 0 填充，计算之后再填充认证数据」课本 p.169——因为 ICV 不可能包含它自己，这是所有 MAC 计算的通例。

✓不变字段 —— 参与计算，正是被保护的内容

  • ID 字段
  • 协议字段

★ 三类字段的分法（针对简答第 3 题）

题目问的是三类，而 PPT 只讲了两类。补上中间那一类就完整了：
· 不变的（immutable）：版本、首部长度、总长度、标识、协议、源地址、目的地址 → 参与计算
· 可变但可预测的（mutable but predictable）：目的地址在使用了源路由选项时——发送方知道包最终会被改成什么样，所以按「最终值」参与计算
· 可变且不可预测的（mutable）：ToS、标志、片偏移、TTL、首部检验和、选项字段 → 置 0 后计算
一句话记：不可预测的才置 0；可预测的按预测值算。

6.3 ★ 抗重放：序列号 + 滑动窗口PPT p.111–112课本 p.169–170，图 6-9

PPT 第 111–112 页 · 问题

序列号单调递增就能防重放了，为什么还要一个「窗口」？

因为网络会乱序。课本 p.170 把理由说得最清楚：「由于 IP 协议是无连接的，且提供不可靠的数据传输服务，即 IP 协议不能保证所有包能按序、可靠地传输到目的地。因此，IPsec 标准接收方应该实现一个大小为 W 的窗口。」

如果没有窗口，只认「比上一个大」会怎样

假设发了 100 101 102，路上乱序成了 102 100 101。接收方收下 102 之后，100 和 101 就都「太小」了 → 全被当成重放丢掉。
——不设窗口的话，正常的网络抖动会被误判成攻击。窗口就是给乱序留的容错余量。

窗口大小 W：PPT p.111 说「固定窗口大小 W（大于 32 的任意值）」，课本 p.170 说「W 的默认值为 64」。两个说法不矛盾——PPT 给的是下限要求，课本给的是默认值。

窗口的右端 N「代表最大的序列号，记录当前收到的合法包的最大序列号」；序列号在 [N−W+1, N] 之间的包已经被正确地接收（即被认证），并在窗口的相应位置上打上标记。

★ 接收方的三条处理规则（PPT p.112 / 课本 p.170，措辞几乎一致）
1
包在窗口中，且是新的
→ 验证消息认证码 MAC。若验证通过，就标记窗口中相应的位置
2
包超过了窗口的右边界，且是新的
→ 验证 MAC 值。若验证通过，就让窗口前进，使得这个序列号成为窗口的右边界，并标记窗口中的相应位置
3
包超过了窗口的左边界，或没有通过 MAC 验证
→ 丢掉这个包，并记录在案（产生审计事件）

★ 注意规则 1 和 2 的共同点：都是「先验证 MAC，通过了才标记」。顺序不能反——否则攻击者随便发一个大序列号就能把窗口推走，把所有正常包挡在左边界之外。这是一个很典型的「先认证后动作」的设计。

序列号溢出怎么办PPT p.112课本 p.169–170

「序列号实现抗重放攻击。初始值是 0，每发送一个包就递增 1，如果到了最大值 2³²−1，发送方会终止当前在用的 SA，用新的密钥重新协商生成新的 SA。」
★ 为什么不能循环回 0：课本给了理由——「否则，一个序列号可能会对应很多合法的包」。序列号一旦重复，抗重放就彻底失效了，因为接收方无法区分「新的 5 号」和「重放的 5 号」。
这也解释了为什么 SAD 里要有「序列号溢出标志」这个必须实现的参数。

6.5 ★ AH 为什么不能穿 NATPPT p.116课本 p.169

PPT 第 116 页 · 结论页

AH 和 NAT 为什么天生不能一起工作？

PPT p.116 那段话已经是完整的答案，它就是课本习题简答第 2 题的标准答案：

PPT p.116 原文

「无论传输模式还是隧道模式，AH 都会认证整个数据包。并且 AH 还会认证位于 AH 头之前的 IP 头。当 NAT 设备修改了 IP 头之后，IPSec 就会认为这是对数据包完整性的破坏，从而丢弃数据包。因此 AH 是不可能和 NAT 在一起工作的。」

把因果链拆开，一共四步：

1
AH 的认证范围包含 IP 首部里的源/目的地址
这两个字段属于「不变字段」，参与 ICV 计算（6.2 节）
2
NAT 的工作恰恰就是改这两个地址
NAT 网关把内网私有地址换成自己的公网地址（3.2 节）
3
接收方重算 ICV，算出来的和包里带的不一样
因为地址已经不是发送方算 ICV 时的那个了
4
接收方判定「被篡改」→ 丢包
而且这个判定是正确的：包确实被改了。AH 没有出错，它工作得很好——只是它无法区分「善意的 NAT」和「恶意的攻击者」。

课本的措辞稍有不同但意思一样：「因此，AH 传输模式和 NAT 不能同时使用，或者说 AH 不能穿越 NAT。」并且特别强调隧道模式也一样：「在隧道模式下，AH 认证的范围也是整个 IP 包，因此前述的 AH 和 NAT 不能兼容的问题同样存在。」课本 p.169

★ 这是一个「安全机制之间互相打架」的经典案例

NAT 是第 3 节讲的安全手段（隐藏内网、当防火墙用），AH 是第 6 节讲的安全手段（保证不被篡改）。两个都是为了安全，凑一块儿却不能用。
根本原因：NAT 的工作方式是「合法地伪造」，而 AH 的工作定义就是「检测一切伪造」。——这类冲突在网络安全里非常普遍，值得记住这个例子。ESP 之所以能兼容，不是因为它更聪明，而是因为它放弃了对 IP 首部的认证（第 7.3 节）。安全性和可用性在这里做了一次明确的交易。

AH 的两种运行模式（图示复述）PPT p.115–117

7.2 ★ 加密范围 ≠ 认证范围PPT p.129课本 p.172

PPT 第 129 页 · 隐含的问题（课本习题简答第 8 题）

ESP 传输模式下，如果使用了加密，为什么 ESP 首部（SPI 和序列号字段）不在加密范围之内？

PPT p.129 用一整段回答了这个问题，课本习题简答第 8 题问的就是它，标准答案也几乎逐字相同。理由有三条，分属两个字段：

① SPI 不能加密 —— 因为它是「解密说明书」

「SPI 是三元组的元素之一，加密后无法确定 SA」。课本说得更完整：「接收端需要 SPI 字段加上源 IP 地址、IPsec 协议来唯一确定对应的 SA，利用该 SA 进行验证、解密等后续处理。如果 SPI 被加密了，就无法找到对应的 SA，也就无法进行后续的验证、解密操作。」
——这是一个「先有鸡还是先有蛋」的问题：要解密就得先知道用哪把钥匙，而「用哪把钥匙」这条信息本身不能被那把钥匙锁着。

② 序列号不必加密 —— 因为它不泄密

「序号字段用于防止重放攻击，因为序号字段不会泄露明文中的机密，所以没有必要加密」。

③ 序列号不加密还有好处 —— 省 CPU

「不加密序号字段也使得一个包不需要经过繁琐的解密过程就可以判断是否重复」。课本补了一句结果：「如果重复则直接丢弃，节省了时间和资源」。
——这和 6.4 节「先查重放后验 ICV」是同一个思路：让最便宜的检查最先发生。

认证数据为什么也不加密？PPT 一并回答了：「如果使用验证，验证数据也不会被加密，因为 SA 需要 ESP 的验证服务，接收端会在进行任何后续处理（检查重放、解密）之前进行验证。数据包只有通过验证后才会进行后续处理。」
课本补充了这样做的收益：「ICV 值是在加密完成后才被计算的，这种处理顺序能够确保在对包解密前就可对接收者的重放或伪造攻击做出快速的检测、处理，从而降低拒绝服务攻击的影响」课本 p.171–172。

★ 一条贯穿本章的设计原则

「便宜的检查放前面，贵的操作放后面；能不做就别做。」这条原则在本章出现了四次：
① ESP 序列号不加密 → 不解密就能查重放（7.2 节）
② ESP 先验证后解密 → 验证不过就不用解密（7.2 节）
③ AH 进入处理先查序列号后验 ICV（6.4 节）
④ AH + ESP 嵌套时先做 ESP 后做 AH → 认证不过就不用解密（8.1 节，课本习题简答第 6 题）
看到「为什么这样排序」的题，先往这个方向想，八成对。

7.3 ESP 与 NAT：为什么它就行PPT p.130, 141课本 p.172–173

对比 AH 看，答案只有一句话
✗ AH 不能穿 NAT

因为它认证 IP 首部（含源/目的地址），而 NAT 恰恰要改这两个字段 → 完整性验证必然失败。

✓ ESP 可以穿 NAT

因为它不认证 IP 首部。PPT p.130 原文：「与 AH 不同，ESP 验证不会对整个 IP 包进行验证，IP 包头部不会被验证。因此 ESP 不存在像 AH 那样的和 NAT 模式冲突问题，因此通信任何一方具有私有地址或者在安全网关背后，仍然可以用 ESP 保护双方通信，因为 IP 头部的地址和其他字段不被验证，可以被 NAT 网关或安全网关修改。」

★ 但这是有代价的，PPT p.130 紧跟着就说了缺点——这半句比前半句更容易考：

ESP 的认证服务比 AH 弱

「因为除了 ESP 头部之外，任何 IP 头部字段都可以修改，只要保证校验和计算正确，接收端就不能检测出修改，所以 ESP 传输模式的验证服务比 AH 弱一些。如果需要更强的验证服务并且通信双方都是公网 IP，应该采用 AH 来认证，或者将 AH 认证和 ESP 认证同时使用。」

课本的说法一致：「当然，不认证 IP 首部也有缺点：如果攻击者修改了 IP 首部，并且保证其校验和计算正确，则接收端就不能检测出攻击者所做的修改。」课本 p.173

这就是「AH 明明什么都不如 ESP，为什么不废掉」的答案：在不需要 NAT、双方都是公网 IP 的场景下，AH 提供的认证覆盖面更大。ESP 的兼容性是拿认证强度换来的。

ESP 隧道模式下的取舍PPT p.133课本 p.173

「隧道模式中，内部的 IP 头被加密和验证，而外部的不能加密也不能验证。」PPT 把两个「不能」的理由分别写了出来，这一对理由非常适合出简答题：

外部 IP 首部为什么不加密

「因为路由器需要这些信息寻找路由」——加密了就没人知道往哪送了。

外部 IP 首部为什么不验证

「是为了能适用于 NAT」——这是主动做出的兼容性让步。

ESP 隧道模式相比传输模式强在哪：「隧道模式下对整个原始 IP 包进行验证和加密，可以提供数据流加密服务；ESP 传输模式下不提供流加密，因为源和目的地址不加密。」代价是「隧道模式占用更多带宽，因为增加了一个 IP 头部」。

PPT p.133 还澄清了一个细节：「两个 IP 头，内部 IP 头部包含真实源和目的 IP，外部可以包含与内部不同的 IP 地址，可以是 NAT 网关地址」。

8.1 ★ 为什么先 ESP 后 AHPPT p.138课本 p.182

PPT 第 138 页 · 老师直接在幻灯片上提的问

为什么 AH 和 ESP 顺序不颠倒一下?

先说清楚「顺序」指的是什么。嵌套使用时的包结构是：

PPT p.138 给的两种模式下的嵌套结构

传输模式：原IP头 | AH | ESP | TCP | ESP尾部

隧道模式：新IP头 | AH | ESP | 原IP头 | TCP | ESP尾部

AH 在外层，ESP 在内层。这意味着：发送时先做 ESP（加密），再做 AH（认证）；接收时反过来，先验 AH，通过了才解 ESP。

老师给的答案（PPT p.138 原文）：

一句话：为了省 CPU

「主要是性能上的考虑，由于解密处理需要大量占用 CPU 和内存，在通过认证（完整性验证）后再进行解密处理会更好一些，如果认证没有通过就不需要执行耗时的解密操作了。」

课本 6.2.6 节把同一件事叫做「先加密后认证」，理由完全一致：「在认证之前进行加密的好处是：接收方会先对发送过来的数据进行完整性验证，只有通过验证的数据才进行解密。如果没有通过完整性验证，就不需要进行耗时的解密工作了。这也是 IPsec 体系结构文档所推荐的 AH 和 ESP 嵌套使用方式。」课本 p.182

★ 课本答案页给的标准答案（简答第 6 题）

题目：「IPsec 体系结构文档中指出，当两个传输模式 SA 被绑定，在同一个端对端流中允许 AH 和 ESP 两种协议，但认为只有先实施 ESP 协议再实施 AH 协议才合适。说明不推荐先实施 AH 协议再实施 ESP 协议的理由。」
标准答案：「主要是性能上的考虑，由于解密处理需要大量占用 CPU 和内存，在通过认证（完整性验证）后再进行解密处理会更好一些，如果认证没有通过就不需要执行耗时的解密操作了。」
——和 PPT p.138 那句话一字不差。这是老师和课本答案完全对齐的一处，几乎可以肯定会考。

课本还给了「先认证后加密」的反向理由（作对比用）课本 p.182

课本很公平地把另一种顺序的好处也列了出来。知道这两条，答题时能显出「我理解的是权衡而不是结论」：

在加密之前进行认证的好处是：
① 「因为加密能保护认证数据，因此一定能够发现传输途中截获数据并更改数据的行为」
② 「如果希望在目的地存储报文的认证信息以便将来查阅，在加密之前进行报文认证更方便，否则需要重新加密报文来验证认证信息」

但 IPsec 最终选了「先加密后认证」——因为抗 DoS 的收益（收到垃圾包立刻能扔）压过了上面这两条。这也呼应了第 7.2 节课本那句「能够确保在对包解密前就可对接收者的重放或伪造攻击做出快速的检测、处理，从而降低拒绝服务攻击的影响」。

两种组合方式课本 p.182

邻传输邻接 transport adjacency

「指在没有激活隧道的情况下，对一个 IP 包使用多个安全协议。」
为什么不能多层：「这种组合 AH 和 ESP 的方法仅考虑了单层组合，更多层次的嵌套不会带来收益，因为所有的处理都是在一个 IPsec 实例中执行的，这个实例就是最终目的地。」

「指通过 IP 隧道应用多层安全协议。在这种方法中，每个隧道均可在路径上不同 IPsec 节点处起始或终止，因此允许多层嵌套。」
两者可以组合使用：「例如，在主机之间使用传输 SA，同时在安全网关间使用隧道 SA」——这正是下面「情况 3」的做法。

9.1 IKE 要解决什么课本 p.173–174

起点 · 一个绕不开的循环

AH 和 ESP 都要用共享密钥。那这把密钥本身，是怎么安全地传过去的？

课本 p.173 先给了两条路：

IPsec 体系结构标准要求支持的两种密钥管理方式

① 手动（manual）：「系统管理员为每个系统手动配置系统自己的密钥和其他系统的密钥」——只适用于规模相对较小且节点配置相对稳定的环境。

② 自动（automated）：「系统能够在需要时通过 IKE 协议自动为 SA 创建密钥」——适用于大型分布式系统。

PPT p.86 讲 SA 管理时给的是同一组对照，措辞更直白：手工维护「容易出错，而且手工建立的 SA 没有生存周期限制，只能通过手工删除，因此有安全隐患」；IKE 自动管理则「不需要管理员手工维护，而且 SA 有生命周期」。PPT p.86

IKE 走的是第二条路。它的底子是 Diffie-Hellman——那个能让双方在公开信道上算出同一个秘密的算法。但 DH 有两个致命缺点，IKE 的全部设计都是在补这两个洞。

Diffie-Hellman 的两优两缺课本 p.174
✓ 两个优点

① 「仅当需要时才生成密钥，减小了将密钥存储很长一段时间而致使遭受攻击的机会」
② 「除对全局参数的约定外，密钥交换不需要事先存在的基础设施」

✗ 两个缺点 —— IKE 要补的就是这两个

① 「没有提供双方身份的任何信息，因此易受中间人攻击」
② 「算法是计算密集型的，容易遭受阻塞性攻击」（攻击者伪造源地址发一堆 DH 公钥，逼你做昂贵的模幂运算）

Cookie 机制是怎么挡住阻塞攻击的课本 p.174–175

先看攻击长什么样：「攻击者伪造合法用户的源地址向受害者发送一个 Diffie-Hellman 公钥。受害者收到后执行模幂运算来计算密钥。重复这类消息可以利用无用工作来阻塞受害者的系统。」

Cookie 交换的解法：「要求各方在初始消息中发送一个伪随机数 Cookie，并要求对方确认。此确认必须在 Diffie-Hellman 密钥交换的第一条消息中重复。如果源地址被伪造，则攻击者就不会收到应答。这样，攻击者仅能让用户产生应答而不会进行 Diffie-Hellman 计算。」

——核心是「先让你证明你收得到回信，再让我干重活」。这和 3.4 节出口过滤那句「远程攻击者可以伪装 IP，但它们并不能接收和回答」是同一个原理。

PPT 未讲ISAKMP 对 Cookie 的三条要求，以及 Cookie 的生成方法（课本 p.175）

「ISAKMP 规定 Cookie 的产生必须满足以下三个基本要求：」

  1. 「Cookie 必须依赖于特定的通信方，从而防止攻击者得到一个正在使用真的 IP 地址和 UDP 端口的 Cookie 时，也无法用该 Cookie 向目标主机发送大量的来自随机选取的 IP 地址和端口号的请求来浪费目标主机的资源」
  2. 「除发起实体外的任何实体都不可能产生被它承认的 Cookie。这就意味着发起实体在产生和验证 Cookie 时，要使用本地的秘密信息，而且根据任何特定的 Cookie 都不可能推断出该秘密信息。实现这个要求的目的在于发起实体不需要保存它产生的 Cookie 的副本，仅在必要时验证收到的 Cookie 应答，这样就降低了泄漏 Cookie 的可能性」
  3. 「Cookie 的产生和验证必须尽可能地快速完成，从而阻止企图通过占用处理器资源的阻塞攻击」

常用的一种生成方法：对以下信息进行 Hash 运算（MD5、SHA1 或其他 HASH 算法）后，取前 64 位：
源IP地址 + 目的IP地址 + UDP源端口 + UDP目的端口 + 随机数 + 当前日期 + 当前时间

PPT 未讲IKE 支持的 Diffie-Hellman 组，与三种身份认证方法（课本 p.175–176）

五个组（前三组用模幂运算的经典 DH，后两组用椭圆曲线）：

  1. 768 比特模的模幂运算：q = 2⁷⁶⁸ − 2⁷⁰⁴ − 1 + 2⁶⁴ × (⌊2⁶³⁸ × π⌋ + 149686)，α = 2
  2. 1024 比特模的模幂运算：q = 2¹⁰²⁴ − 2⁹⁶⁰ − 1 + 2⁶⁴ × (⌊2⁸⁹⁴ × π⌋ + 129093)，α = 2
  3. 1536 比特模的模幂运算：参数特定
  4. 基于 2¹⁵⁵ 的椭圆曲线组：生成器参数 X = 7B, Y = 1C8；椭圆曲线参数 X = 0, Y = 7338F
  5. 基于 2¹⁸⁵ 的椭圆曲线组：生成器参数 X = 18, Y = D；椭圆曲线参数 X = 0, Y = 1EE9

三种身份认证方法：

  1. 数字签名：「用双方均可以得到的散列值来进行签名，每一方都用自己的私钥加密散列值。散列值使用重要的身份参数（如用户 ID、现时值）来生成」
  2. 公钥加密：「利用对方的公钥对用户身份参数（如用户 ID、现时值）加密来进行身份认证」
  3. 对称密钥加密：「通过带外机制得到密钥，并且该密钥对交换的身份参数进行加密，从而实现对密钥交换过程的身份认证」

IKEv2 的变化：「对于 Diffie-Hellman 算法，规定使用椭圆曲线群上对素数求模。对于认证，也使用了椭圆曲线上的数字签名。早期的 IKEv2 文档使用的是基于 RSA 的数字签名。与 RSA 相比，使用 ECC 可以用更短的密钥就能达到相当或更高的安全强度。」

9.3 ★ IKEv1：主模式 vs 积极模式课本 p.176–177，图 6-13

先搞清「两个阶段」这个框架

第一阶段：「双方交换有关密码算法的信息、包括现时值及 Diffie-Hellman 值在内的其他双方愿意使用的安全参数。这轮交换的最终结果是双方建立了一个称为 IKE SA 的特殊安全关联，该 SA 定义了通信双方随后要在其上进行消息交换的安全通道的参数。因此，随后（第二阶段）的任何 IKE 消息交换都受到加密和消息认证保护。」

第二阶段：「通信双方相互认证、建立第一个 IPsec SA，并将其保存在 SAD 中，为后续的 AH 或 ESP 安全通信所用。」

★ 两个 SA 千万别混：IKE SA 是「保护协商过程本身」的，IPsec SA 才是「保护你的数据」的。先用第一阶段建一条安全的谈判桌，再在桌上谈数据怎么保护。

IKEv1 的四种交换模式课本 p.176

「IKEv1 定义了 4 种密钥交换模式：主模式、积极模式、快速模式和新组模式。前三种模式用于协商 SA，最后一个用于协商 Diffie-Hellman 算法所用的组。

9.4 IKEv2 的三处改进课本 p.177–178

课本先给了个总纲：「IKEv2 保留了 IKEv1 的大部分特性，IKEv1 的一部分扩展特性（如 NAT 穿越）作为 IKEv2 协议的组成部分被引入 IKEv2 框架中。」下面三条是实打实的改进：

1请求—响应成对出现

「与 IKEv1 不同，IKEv2 中所有消息都以『请求-响应』的形式成对出现，响应方都要对发起方发送的消息进行确认，如果在规定的时间内没有收到确认报文，发起方需要对报文进行重传处理，提高了安全性。」

2防御 DoS 攻击

问题：「在 IKEv1 中，当网络中的攻击方一直重放消息，响应方需要通过计算后，对其进行响应而消耗设备资源，造成对响应方的 DoS 攻击。」
IKEv2 的解法：「响应方收到请求后，并不急于计算，而是先向发起方发送一个 Cookie 类型的 Notify 载荷（即一个特定的数值），两者之后的通信必须保持 Cookie 与发起方之间的对应关系，从而有效防御了 DoS 攻击。」——还是 Cookie 那一招，但用在了协议正文里。

3交换次数大幅减少

「IKEv2 通过初始交换就可以完成一个 IKE SA 和第一对 IPsec SA 的协商建立，对应 IKEv1 的第一阶段。如果要求建立的 IPsec SA 多于一对时，每一对 SA 值只需要额外增加一次创建子 SA 交换（而 IKEv1 仍然需要经历两个阶段）。」
「与 IKEv1 相比，IKEv2 在保证安全性的前提下，减少了传递的信息和交换的次数。」

★ IPv6 vs IPSec：安全上相同，可行性上差远了
从安全方面看 —— 本质相同

「IPv6 和 IPSec 本质上是相同的，两者都提供强的身份鉴别、加密和 VPN 支持，很多 IPv6 和 IPSec 的特点都基于相同的 RFC 规范。」
——不奇怪：IPsec 本来就是为 IPv6 设计的，只是后来回头补了对 IPv4 的支持。

从可行性方面看 —— 差得远

「从 IPv4 转换到 IPv6，路由器和网络设备必须更新以支持 IPv6 协议；相反，任何支持 IPv4 的路由器也能支持 IPSec，仅需源和目的站支持，而无须中间系统支持。」

★ 这一对比就是标准的简答答案：IPsec 是端到端的（只要两头会说就行，中间的路由器完全不用知道），IPv6 是逐跳的（整条路径上每一台设备都得换代）。安全能力 IPv6 ≈ IPSec，部署代价 IPSec ≪ IPv6——这就是为什么 IPv4 + IPsec 这个组合活了三十年。

课本给了同一件事的另一面：「在 IPv6 中，IPsec 是必须支持的，但在 IPv4 中，则是可选的」课本 p.161——「必选 vs 可选」这组词也常出现在选择题里。

「为解决 IPv4 地址资源数量不足、安全性、服务质量等问题，IETF 设计了下一代 IP 协议 IPv6，用于替代 IPv4 协议。」

1IPv4 向 IPv6 过渡技术的安全风险

双协议栈：「黑客可以利用这两种协议中存在的安全弱点和漏洞进行协调攻击，或者利用两种协议版本中安全设备的协调不足来逃避检测。并且，双协议栈中一种协议的漏洞可能会影响另一种协议的正常工作。」
隧道机制：「由于隧道机制对任何来源的数据包只进行简单的封装和解封，而不对 IPv4 和 IPv6 地址的关系做严格的检查，所以隧道机制的引入，会给网络安全带来更复杂的问题，甚至安全隐患。」

2无状态地址自动配置的安全风险

根源是邻居发现协议（NDP）带来的即插即用。三种具体攻击：
· 假冒路由器：「恶意主机可以假冒合法路由器发送伪造的 RA 报文，在 RA 报文中修改默认路由器为高优先级，使 IPv6 节点在自己的默认路由器列表中选择恶意主机为默认网关，从而达到中间人攻击的目的」（——和第 2.3 节的 DHCP 假分配一模一样的套路）
· 破坏 DAD（重复地址检测）：「IPv6 节点在无状态自动配置链路本地或全局单播地址的时候，需先设置地址为临时状态，然后发送 NS 报文进行 DAD 检测，恶意主机这时可以针对 NS 请求报文发送假冒的 NA 响应报文，使 IPv6 节点的 DAD 检测不成功，从而使 IPv6 节点停止地址的自动配置过程」（——让你永远配不上地址，是一种 DoS）
· 前缀重新编址攻击：「恶意主机通过发送假冒的 RA 通告，从而造成网络访问的中断」

3IPv6 中 PKI 管理系统的安全风险

「IPv6 的加密和认证需要 PKI 的支持。PKI 系统在 IPv6 中应用时，由于 IPv6 网络的用户数量庞大，设备规模巨大，因此证书注册、更新、存储、查询等操作很频繁，面临的主要挑战包括：
一是要求 PKI 能够满足高访问量的快速响应并提供及时的状态查询服务；
二是 IPv6 中认证实体规模巨大，PKI 证书的安全管理的复杂性将大幅增加。」

4IPv6 编址机制的隐患

「面对庞大的地址空间，漏洞扫描、恶意主机检测等安全机制的部署难度将激增。IPv6 引入了 IPv4 兼容地址、本地链路地址、全局聚合单播地址和随机生成地址等全新的编址机制。
其中，本地链路地址可自动根据网络接口标识符生成而无须 DHCP 自动配置协议等外部机制干预，实现不可路由的本地链路级端到端通信，因此移动的恶意主机可以随时连入本地链路，非法访问甚至是攻击相邻的主机和网关。」
——地址空间大是优点也是缺点：攻击者扫不完，防守方也管不过来。

5IPv6 的安全机制对网络安全体系的挑战

首先，网络层加密带来的隐患：
① 针对密钥的攻击——「在 IPv6 下，IPsec 的两种工作模式都需要交换密钥，一旦攻击者破解到正确的密钥，就可以得到安全通信的访问权，监听发送者或接收者的传输数据，甚至解密或篡改数据」
② 加密耗时过长引发的拒绝服务攻击——「加密需要很大的计算量，如果黑客向目标主机发送大规模看似合法事实上却是任意填充的加密数据包，则目标主机将耗费大量 CPU 时间来检测数据包而无法回应其他用户的通信请求，造成拒绝服务攻击」
其次：「IPv6 的加密传输对传统防火墙和入侵检测系统的影响较大，已有的一些网络防护功能无法实现，给网络带来了新的安全风险。」
——这一条最值得记：加密是双刃剑。防火墙和 IDS 靠「看得见内容」工作，你把内容加密了，它们也瞎了。

11.1 AS / IGP / EGP课本 p.188

为什么要分自治系统

「为了降低路由动态更新的复杂性，因特网将整个互联网划分为许多较小的自治系统（Autonomous System, AS）。一个自治系统是一个互联网，其最重要的特点就是它有权自主地决定在本系统内应采用何种路由选择协议。」

★ 判定一个 AS 的两个条件（课本的例子很关键）：「一个自治系统内的所有网络都属于一个行政单位（例如，一个公司、一所大学、政府的一个部门）来管辖。但一个自治系统的所有路由器都必须是在本自治系统内连通的。如果一个部门管辖两个网络，但这两个网络要通过其他的主干网才能互连起来，那么这两个网络并不能构成一个自治系统，它们还是两个自治系统。」
——注意：同一个行政单位不等于同一个 AS，还必须「内部连通」。这个细节容易出判断题。

11.2 RIP 及其脆弱性课本 6.4.1（p.188–191）

RIP 的机制：三条处理策略

RIP 是基于距离向量的路由选择协议，「其最大优点就是简单」。三个版本：RIPv1（RFC 1058）、RIPv2（RFC 1723）和 RIPng（用于 IPv6）。

距离的定义：「从一个路由器到直接连接的网络的距离定义为 1。从一个路由器到非直接连接的网络的距离定义为所经过的路由数加 1。」★ 「加 1」的理由课本特意解释了：「因为到达目的网络后就进行直接交付，而到直接连接的网络的距离已经定义为 1」。

★ 必背的数字：「RIP 允许一条路径最多只能包含 15 个路由器。因此『距离』为最大值 16 时即相当于不可达。可见 RIP 只适用于小型互联网。」

1和谁交换

「仅和相邻路由器交换信息。两个路由器是相邻的，如果它们之间的通信不需要经过另一个路由器。换言之，两个相邻路由器在同一个网络上都有自己的接口。RIP 协议规定，对不相邻的路由器就不交换信息。」

2交换什么

「交换的信息是当前本路由器所知道的全部信息，即自己的路由表。因此，交换的信息就是：『到本自治系统中所有网络的（最短）距离，以及到每个网络应经过的下一跳路由器』。」

3什么时候交换

「按固定的时间间隔交换路由信息，例如，每隔 30 秒。然后路由器根据收到的路由信息更新路由表。当网络拓扑发生变化时，路由器也及时向相邻路由器通告拓扑变化后的路由信息。」

控制路由更新周期，30s
无效定时器
探测网络故障，180s。「如果在该时间内，不能从前面操作的相邻路由器接收路由更新报文，那么所有经由该相邻路由器的路由均被标记为无效，并进入保持状态」
保持定时器

240s。「如果某路由失败，并在失败后 240s 内仍然无效，那么路由表中的该路由项将被刷新。刷新定时器的超时将使无效路由被从路由更新报文中删除」

另外：「RIP 定义了两类报文：更新报文（用于路由表的分发）和请求报文（用于路由器发现网上其他运行 RIP 协议的路由器）。RIP 协议报文使用 UDP 协议进行传送。」

11.3 ★ OSPF：三种认证 + 五类攻击课本 6.4.2（p.191–194）

OSPF 与 RIP 的三点根本差别

OSPF 使用分布式链路状态协议（Link State Protocol）。三条策略正好和 RIP 逐条对立：

RIP（距离向量）OSPF（链路状态）
发给谁仅向自己相邻的几个路由器发送洪泛法（Flooding）——「向本自治系统中所有路由器发送信息」，即「路由器通过所有输出端口向它所有相邻的路由器发送信息。而每一个相邻路由器又再将此信息发往其所有的相邻路由器（但不再发送给刚刚发来信息的那个路由器）」
发什么「到所有网络的距离和下一跳路由器」——是自己的整张路由表「与本路由器相邻的所有路由器的链路状态，但这只是路由器所知道的部分信息」。链路状态 = 本路由器和哪些路由器相邻，以及该链路的「度量 metric」（表示费用、距离、时延、带宽等，由网络管理人员决定）
什么时候发不管拓扑有无变化，都要定期交换「只有当链路状态发生变化时，路由器才用洪泛法向所有路由器发送此信息」

★ 结果上的差别：OSPF 的链路状态数据库（LSDB）「实际上就是全网的拓扑结构图」，「这个拓扑结构图在全网范围内是一致的（这称为链路状态数据库的同步）」，每个路由器用 Dijkstra 最短路径算法算出自己的路由表。而 RIP「虽然知道到所有网络的距离以及下一跳路由器，但却不知道全网的拓扑结构（只有到了下一跳路由器，才能知道再下一跳应当怎样走）」。
另外两个数字：OSPF 规定每两个相邻路由器每隔 10 秒钟要交换一次问候报文；若有 40 秒钟没有收到某个相邻路由器发来的问候报文，则认为该相邻路由器是不可达的。为确保 LSDB 与全网状态一致，还规定每隔一段时间，如 30 分钟，要刷新一次数据库中的链路状态。OSPF 不用 UDP 而是直接用 IP 数据报传送其报文（协议字段值为 89）。

OSPF 的五类报文
  1. 类型 1，问候（Hello）报文——用来发现和维持相邻路由器的可达性。「在正常情况下，网络中传送的绝大多数 OSPF 报文都是问候报文」
  2. 类型 2，数据库描述（Database Description）报文——向相邻路由器给出自己的链路状态数据库中所有链路状态项目的摘要信息
  3. 类型 3，链路状态请求（LSR）报文——向对方请求发送某些链路状态项目的详细信息
  4. 类型 4，链路状态更新（LSU）报文——用洪泛法向全网发送更新的链路状态
  5. 类型 5，链路状态确认（LSAck）报文——对链路更新报文的确认
★ OSPF 定义的三种认证方式（习题选择第 20 题）

「OSPF 定义了三种认证方式：空认证（NULL，即不认证，类型为 0）、简单口令认证（类型为 1）、MD5 加密身份认证（类型为 2）。OSPF 报文格式中有两个与认证有关的字段：认证类型（AuType, 16 位）、认证数据（Authentication, 64 位）。」

★ 习题第 20 题「下列认证方式中，不属于 OSPF 协议定义的认证方法是（　）」→ 答 D：SHA-1 加密认证（OSPF 只有 NULL、简单口令、MD5 三种）。

认证方式课本原文
空认证
类型 0		「路由配置中的默认认证方式是不认证，此时认证数据字段不包含任何认证信息，即在路由信息交换时不提供任何额外的身份验证。接收方只须验证 OSPF 报文的校验和（checksum）无误即可接收该报文，并将其中的 LSA（Link State Advertisement）加入链路状态数据库中。因此，不认证的安全性最低。」
简单口令认证
类型 1		「认证数据字段填写的是口令值。由于 OSPF 报文包括口令都是以明文形式传输的，接收方只须验证它的校验和无误且验证数据字段值等于设定的口令，就会接收该报文。攻击者可以通过嗅探程序监听到这个口令，一旦获得了口令就可以生成新的伪造的 OSPF 报文，发送给该接口的各路由器。因此，不认证和简单口令认证都有可能遭到重放和伪造攻击。」
MD5 加密认证
类型 2		「同一个网络或子网的所有 OSPF 路由器共享一个密钥。当一个报文传输到此网络时，OSPF 路由器使用这个密钥为 OSPF 报文签名，合法的路由器接收到此报文可以验证签名的有效性，从而确定报文的正确性。报文即使被攻击者截获也无法从签名中恢复出密钥，因而无法对修改后的报文或新加的伪报文签名。同时，加密身份认证使用非递减的加密序列号来防止重放攻击。
★ 两条局限（重要）：① 「但当序列号从最大值回滚到初值或路由器重启后，重放攻击仍能发生」；② 「如果攻击者来自内部，则加密认证对有密钥的内部攻击者是无效的」（共享密钥的通病）

OSPF 认证的三个层次：「OSPF 协议可以对接口、区域、虚链路进行认证。接口认证要求在两个路由器之间必须配置相同的认证口令。区域认证是指所有属于该区域的接口都要启用认证，因为 OSPF 以接口作为区域分界。区域认证接口与邻接路由器建立邻居需要有相同的认证方式与口令，但在同一区域中不同网络类型可以有不同的认证方式和认证口令。配置区域认证的接口可以与配置接口认证的接口互相认证，使用 MD5 认证口令 ID 要相同。」

★ 常见的五类 OSPF 攻击（简答第 10 题）
1最大年龄（MaxAge）攻击

「LSA 的最大年龄（MaxAge）为 1 小时，攻击者发送带有最大 MaxAge 设置的 LSA 信息报文，这样，最开始的路由器通过产生刷新信息来发送这个 LSA，而后就引起在 age 项中的突然改变值的竞争。如果攻击者持续地突然插入这类报文给整个路由器群，将会导致网络混乱和拒绝服务攻击。」

2序列号加 1（Sequence++）攻击

「根据 OSPF 协议的规定，LSA Sequence Number（序列号）字段是被用来判断旧的或者是同样的 LSA，序列号越大表示这个 LSA 越新。当攻击者持续插入比较大的 LSA 序列报文号时，最开始的路由器就会产生发送自己更新的 LSA 序列号来超过攻击者序列号的竞争，这样就导致了网络不稳定和拒绝服务攻击。」

3最大序列号攻击

「根据 OSPF 协议的规定，当发送最大序列号（0x7FFFFFFF）的网络设备再次发送报文（此时为最小序列号）前，要求其他设备也将序列号重置，OSPF 停 15 分钟。这样，如果攻击者插入一个最大序列号的 LSA 报文，将触发序列号初始化过程，理论上就会马上导致最开始的路由器的竞争。但在实践中，在某些情况下，拥有最大序列号的 LSA 并没有被清除，而是在连接状态数据库中保持一小时的时间。如果攻击者不断地修改收到的 LSA 的序列号，就会造成网络运行的不稳定。」

4重放攻击

Hello 报文的重放攻击，有两种方式：
①「报文中列出最近发现的路由器，所以如果攻击者重放 Hello 报文给该报文的产生者，产生者不能在列表中查找到自己，则认为该链路不是可双向通信的，将设置邻居的状态为 Init 状态，阻止建立邻接关系」
②「更高序列号攻击，是指攻击者重放一个 Hello 报文，该报文比源路由器发送的报文具有更高的序列号，目的路由器将忽略真实的报文，直到收到一个具有更高序列号的报文。如果在 Router-Dead Interval 内目的路由器没有收到 Hello 报文，将不能维持邻居关系」

LSA 报文的重放攻击：「攻击者重放一个与拓扑不符的 LSA，并直接泛洪出去，而且该 LSA 必须被认为比当前的新。各路由器接收到后，会触发相应的 SPF 计算（计算最小路径树的过程）。当源路由器收到重放的 LSA 时，将泛洪一个具有更高序列号的真实 LSA，各路由器收到后，更新 LSA，势必又会触发 SPF 计算。SPF 计算是一个很消耗资源的操作，频繁的 SPF 计算会导致路由器性能的下降。」

5篡改攻击

「IP 首部的一些敏感字段的正确与否直接关系到 OSPF 路由的安全。IP 首部的源 IP 地址、目的 IP 地址字段分别标识 OSPF 分组由哪个路由器发出的、分组要发送到哪个路由器，协议号字段置为 89 时表明封装的是 OSPF 分组。所有这些字段如果被修改，都会导致 OSPF 路由陷入混乱。」

★ 一个关键的协议缺陷：「在 OSPFv2 中，采用加密认证情况下，由于计算消息摘要时并未包含 IP 首部，所以无法保证 IP 首部未被修改。」两个具体问题：
① 源地址：「在广播网、点对多点、NBMA 网络上，协议要根据 IP 首部中的源地址来区分不同的邻居发送的报文」
② 目的地址：「在 IP 层根据目的地址决定是否接受该报文，因此，通过修改 IP 首部的源地址和目的地址，可以扰乱正常的协议运行」
——这正是 AH 认证 IP 首部的价值所在。OSPFv2 自己的认证不盖 IP 首部，所以有这个洞；而 OSPFv3 干脆不自带认证，改用 IPsec。

OSPFv3 的做法：「同 RIPng 一样，OSPFv3 协议自身不再有加密认证机制，取而代之的是通过 IPv6 的 IPsec 协议来保证安全性，路由协议必须运行在支持 IPsec 的路由器上。IPsec 可确保：路由器报文来自于授权的路由器；重定向报文来自于被发送给初始包的路由器；路由更新未被伪造。」

11.4 ★ BGP 劫持与「数字大炮」课本 6.4.3（p.194–196）

BGP 的机制要点

「BGP 协议是一种应用于 AS 之间的边界路由协议，而且运行边界网关协议的路由器一般都是网络上的骨干路由器。」

传输协议
「运行 BGP 协议的路由器相互之间需要建立 TCP 连接以交换路由信息，这种连接称为 BGP 会话（session）」
对等关系
「每一个会话包含了两个端点路由器，这两个端点路由器称为相邻路由器（neighbor）或对等路由器（peer）。BGP 一般是在两个自治系统的边界路由器之间建立对等关系，当然也可以在同一个自治系统内的两个边界路由器之间建立对等关系，前者称为 EBGP，后者则称为 IBGP」
BGP 发言人
「在配置 BGP 时，每一个自治系统的管理员要选择至少一个路由器作为该自治系统的『BGP 发言人』。一般说来，两个 BGP 发言人都是通过一个共享网络连接在一起的，而 BGP 发言人往往就是 BGP 边界路由器，但也可以不是」
不自动发现邻居
「在工作之前，BGP 协议并不会主动地进行 BGP 邻居的发现，而是必须通过手工指定的方式进行配置」
路由算法
「由于 BGP 只能是力求寻找一条能够到达目的网络且比较好的路由（不能兜圈子），而并非要寻找一条最佳路由。因此，BGP 协议采用路径向量（Path Vector）路由选择协议，它与距离向量协议和链路状态协议都有很大的区别」

四种主要报文：① 打开（open）报文，用来与相邻的另一个 BGP 发言人建立关系；② 更新（update）报文，用来发送某一路由的信息以及列出要撤销的多条路由；③ 保活（keep alive）报文，用来确认打开报文和周期性地证实相邻路由器关系；④ 通知（notification）报文，用来发送检测到的差错。

★ 两个细节：「保活报文只有 19 字节长（只用 BGP 报文的通用首部），因此不会造成太大的网络开销」，两个 BGP 发言人周期性地交换保活报文，一般间隔 30 秒。「撤销路由可以一次撤销许多条，而增加新路由时，每个更新报文只能增加一条。」

课本 p.196 · BGP 最核心的安全问题

BGP 凭什么相信另一个自治系统说的话？

不凭什么。课本一句话点破：「BGP 协议最主要的安全问题在于缺乏一个安全可信的路由认证机制，即 BGP 无法对所传播的路由信息的安全性进行验证。」

于是就有了 BGP 路由劫持

「每个自治系统向外通告自己所拥有的 CIDR（Classless Inter-Domain Routing）地址块，并且协议无条件信任对等系统的路由通告，这就导致一个自治系统向外通告不属于自己的前缀时，也会被 BGP 用户认为合法，从而接受和传播，导致路由攻击的发生，特别是 BGP 路由劫持攻击，严重威胁网络的安全。」

定义：「BGP 路由劫持攻击是指攻击者利用 BGP 协议存在的认证问题诱导一个网络将网络内的流量发送至错误的目的地，从而实现对目标网络流量的拦截、嗅探或者篡改。」

——注意它和 11.2 节 RIP 那个「宣称自己到哪儿都最便宜」是同一个招式，只不过 BGP 的作用域是整个互联网。

课本给的真实事件（这些年份和公司名很适合出选择题）

「近年来，全球几乎每年都会发生有意攻击或操作失误引起的 BGP 路由劫持事件：
· 2018 年 4 月，攻击者利用 BGP 劫持对指向 Amazon Web Services（AWS）服务的流量进行了重新路由，借此对以太坊钱包网络发动网络钓鱼攻击
· 2017 年 12 月，某互联网服务供应商针对谷歌、Facebook、苹果以及微软等大型企业的网站进行了网络流量 BGP 劫持
· 在此 8 个月之前，另一家互联网服务供应商亦曾对 Visa、MasterCard 以及赛门铁克网站的流量进行 BGP 劫持

——最后一条特别值得记：BGP 劫持不一定是攻击，配置错误一样能打瘫一个国家。

应对措施：SIDR / ROV / RPKI / BGPsec

★ 「数字大炮」CXPST（习题选择第 21 题 + 简答第 11 题）

★ 习题第 21 题：「『数字大炮』利用（　）协议的脆弱性实施网络攻击」→ 答 C：BGP。

出处：「2011 年美国明尼苏达大学 M.Schuchard 等人在 NDSS2011 国际会议上提出了一种基于 BGP 协议漏洞的 CXPST（Coordinated Cross Plane Session Termination）攻击方法，俗称『数字大炮』。」

攻击原理（简答第 11 题的答案）：「这种攻击利用 BGP 路由器正常工作过程中的路由表更新机制，通过在网络上制造某些通信链路的时断时续的震荡效应，导致网络中路由器频繁地更新路由表，最终当网络上震荡路径数量足够多、震荡的频率足够高时，网络上所有路由器都处于瘫痪状态。」

具体做法：「对一个给定的网络，选取网络的两个节点 A 和 B，计算 AB 之间的关键路径，然后以关键路径作为震荡路径，采用一定的攻击策略，如 ZMW 攻击算法来实现对关键路径的 DDoS 攻击，从而导致连接关键路径的路由器侦测到其连接链路上处于时断时续的状态。因此，当两个路由器之间的链路处于断开时，路由器会自动更新其路由表，同时将路由表更新信息发送给其相邻的路由器……如此循环往复，路由表更新信息在整个网络中被扩散传递。」

★ 威力（这个数字很吓人，也很好记）：「相关实验表明：如果在互联网上建立一个由 25 万台『肉鸡』组成的僵尸网络，对互联网的关键路径发起拒绝服务攻击，那么可在 300 秒之内导致骨干路由器的处理延时在 200 分钟以上，也就意味着骨干路由器陷入瘫痪状态。」

★ 防御措施（简答第 11 题的后半问）——课本坦承基本无解：「对于数字大炮，现有的 BGP 内置故障保护措施几乎无能为力。
· 方法一：「通过一个独立网络来发送 BGP 更新，但这不太现实，因为这必然涉及建立一个影子互联网」
· 方法二：「改变 BGP 系统，让其假定连接永不断开，但根据研究者的模型，此方法必须让互联网中至少 10% 的自治系统做出这种改变，并且要求网络运营者寻找其他办法监控连接的健康状况，但是要说服足够多的独立运营商做出这一改变非常困难」

★ BGP 的其他安全问题（补全简答题）

① 继承自 TCP 的问题：「由于 BGP 协议使用 TCP 作为其传输协议，因此同样会面临很多因为使用 TCP 而导致的安全问题，如 SYN Flood 攻击、序列号预测等。BGP 没有使用它们自身的序列号而依靠 TCP 的序列号，因此，如果设备采用了可预测序列号方案的话，就存在这种类型的攻击。」
② 认证配置不到位：「由于 BGP 主要在核心网的出口中应用，因此一般都会采用密码认证。但是，部分 BGP 的实现默认情况下没有使用任何认证机制，而有些可能还使用明文密码。在这种情况下，攻击者发送 UPDATE 信息来修改路由表的远程攻击的机会就会增加许多。」

★ 简答第 12 题的完整答案

「简要论述在 IPv4 网络和 IPv6 网络中，路由协议的安全机制和保护措施有什么不同。」
标准答案（答案页 p.487）：「在 IPv4 网络中，路由协议的安全需要路由协议本身来完成，而在 IPv6 网络中，可以利用 IPv6 中的 IPsec 协议提供的认证和加密服务来保证其安全。」
展开举证（课本 p.188、191、194）：IPv4 侧——RIPv2 自带明文/MD5 认证，OSPFv2 自带 NULL/简单口令/MD5 三种认证；IPv6 侧——RIPng 和 OSPFv3 都不再自带加密认证机制，改为依赖 IPsec 的 AH 认证与 ESP 加密。把这个「自带 vs 外包」的转变说清楚，这道题就满分了。

容易混的怎么区分
SPD vs SADSPD 回答「要不要保护、怎么保护」（策略层，PPT p.137：「类似于防火墙的配置规则」）；SAD 回答「用哪把密钥、哪个算法、序号到几了」（参数层，像连接状态表）。SPD 里一条「保护」策略会指向 SAD 里的一个 SA。
IKE SA vs IPsec SAIKE SA 保护「协商过程本身」（第一阶段建立，是一条安全的谈判桌）；IPsec SA 保护「你的数据」（第二阶段建立，存进 SAD 供 AH/ESP 用）。
AH 不能穿 NAT
vs
ESP 能穿		唯一原因：AH 认证 IP 首部（含源/目的地址），ESP 不认证。
代价：ESP 的认证服务因此弱于 AH——「除了 ESP 头部之外，任何 IP 头部字段都可以修改，只要保证校验和计算正确，接收端就不能检测出修改」。
传输模式
vs
隧道模式		判据只有一条：只要 IPSec 一方是安全网关或路由器，就必须用隧道模式。
理由（PPT p.102）：路由器「不会也不应该修改 IP 头部以外的其他内容」，插传输模式的头就「违反了路由器的规则」。
PPT 的「路由风险」
vs
课本的「路由安全」		PPT p.35–39：通用攻击分类（直接攻击、表中毒、表淹没、度量攻击、环路攻击），不提任何具体协议。
课本 6.4：RIP / OSPF / BGP 三个协议各自的脆弱性。两边内容完全不重叠。
ARP vs RARPARP：已知 IP → 查 MAC；RARP：已知 MAC → 查 IP。两者都是广播请求、单播回答，而且仅限本地——「ARP 分组并不通过网桥、路由器和网关」。
ARP 投毒：
DoS vs MitM		同样是重写 ARP 表：填「坏的 MAC」→ DoS（包送到不存在的地址）；填「攻击者自己的 MAC」→ 中间人（攻击者收下再转发）。区别只在填什么。
NAT vs RNAT表是谁建的：NAT 的中继表由内部主机发起连接时动态建立（所以外部连不进来 → 有防火墙效果）；RNAT 的映射由管理员静态配置（所以外部能连进来 → 能对外提供服务）。
PPT p.62 题眼：「NAT 提供防火墙功能，而 RNAT 允许面向服务的应用。」
IKE 三种防护
各防什么		Cookie 机制 → 防拥塞（阻塞）攻击（习题 17）
现时值 Nonce → 防重放攻击（习题 18，你书上写错的那道）
身份认证 → 防中间人攻击（习题 19）
口诀：拥塞用 Cookie，重放用 Nonce，中间人用认证。

出处问题一句话答案
PPT p.7混杂模式是被动收听，怎么可能被发现？链路层不过滤了，高层协议照常回答。发一个「MAC 无效但 IP 有效」的 ARP，谁回谁露馅。
PPT p.74课本 p.162 图 6-2 错在哪？DOI 和 IKE 是并列的两个组成部分，不是上下级。课本把 IKE 画在了 DOI 之下。
PPT p.99AH 的认证范围到底是什么？整个分组，除了（外部）IP 首部的可变字段——不是「仅载荷」，也不是「整个包」。
PPT p.102既然传输模式更省带宽，为什么还要隧道模式？不是为了更安全，是硬性约束：路由器「不会也不应该修改 IP 头部以外的内容」，插传输模式的头违反路由器规则。
PPT p.106学 AH / ESP 要关注哪三件事？① 加密与认证的范围　② 两种模式的差别　③ 与 NAT 的兼容性。这是老师给的答题框架。
PPT p.116AH 为什么不能和 NAT 一起工作？AH 认证包含源/目的 IP 地址，NAT 恰恰改这两个 → ICV 必然对不上 → 丢包。隧道模式同样不行。
PPT p.129ESP 为什么不加密 SPI 和序列号？SPI 是「解密说明书」本身（加密了就找不到 SA）；序列号不泄密，且不加密才能在解密前查重放。
PPT p.129ESP 的认证数据为什么也不加密？接收端要在任何后续处理（查重放、解密）之前先验证。「数据包只有通过验证后才会进行后续处理。」
PPT p.130ESP 传输模式下改了 IP 首部能被发现吗？不能——IP 首部不在认证范围内。所以 ESP 的认证服务弱于 AH；要强认证就用 AH 或两者同时用。
PPT p.133隧道模式的外部 IP 首部为什么既不加密也不认证？不加密是因为路由器要读它寻路；不认证是为了能适应 NAT。
PPT p.138为什么 AH 和 ESP 顺序不颠倒？性能：解密贵，认证便宜。先认证不过就不用解密了。（与课本答案一字不差）
PPT p.139ESP 与 AH 的区别？PPT 未作答ESP 多了加密，少了对 IP 首部的认证。多的让它能保密、能穿 NAT；少的让它认证弱于 AH。
课本 p.174Diffie-Hellman 有什么毛病，要 IKE 来补？两条：不提供身份信息 → 易受中间人；计算密集 → 易受阻塞攻击。分别用身份认证和 Cookie 补。
课本 p.177主模式多花 3 条消息买到了什么？身份保护。主模式的 ID 在加密通道里发；积极模式「没有对身份信息进行加密保护」，第一条消息就暴露了发起方是谁。
